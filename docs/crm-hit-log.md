# יומן כניסות ל-/crm (זמני)

**למה:** בדוח GA4 מופיעה ריצה אוטומטית בכל יום עבודה ב-09:00 (37-39 סשנים,
18-19 כתובות של `/crm`, פרוקסים מתחלפים). ב-Supabase היא לא נראית, כי היא לא
מתחברת, ו-Log Drains של Netlify זמין רק ב-Enterprise. בלי לוג גישה אין דרך
לראות מי מבקש את ה-HTML.

**מה:** `netlify/edge-functions/crm-hit-log.ts` כותבת שורת JSON לכל בקשה
ל-`/crm` ול-`/crm.html`, ומחזירה את התשובה כמו שהיא (`context.next()`).
כשל בכתיבה נבלע.

## איפה רואים

Netlify ← הפרויקט ← `Logs & metrics` ← `Edge functions` ← `crm-hit-log`.
מחפשים `crm_hit`. הלוגים נשמרים זמן קצר (תלוי בתוכנית), לכן מוציאים את
החלון של 09:00 (07:00 UTC בחורף, 06:00 בקיץ) ושומרים כקובץ.

## מה נרשם

| שדה | הערה |
| --- | --- |
| `ts`, `method`, `path`, `status` | |
| `goto` | רק אם מהצורה `accXxx`, אחרת `other` או ריק |
| `params` | **שמות** הפרמטרים המוכרים של ה-CRM בלבד (`KNOWN_PARAMS`), וכל שם אחר כ-`other`. אף ערך (`wc`, `token`, מזהים) לא נרשם |
| `ua`, `ch_ua`, `ch_mobile`, `ch_platform`, `lang` | טביעת האצבע של הדפדפן |
| `dest`, `site` | `Sec-Fetch-*`: דפדפן אמיתי שולח, כלי HTTP בדרך כלל לא |
| `ref` | שם מארח בלבד |
| `country`, `city` | מ-`context.geo` |
| `ip24` | `/24` ב-IPv4, `/48` ב-IPv6 |

## איך מפענחים

- **`ch_ua`, `dest` ו-`site` ריקים** ו-`ua` של Chrome: כלי HTTP שמתחזה, לא דפדפן.
- **`ua` כולל `HeadlessChrome`** או `Lighthouse`: דפדפן אוטומטי שלא הסתיר.
- **אותו `ua` מ-`country` שונים ב-`ip24` שונים** באותה דקה: מאגר פרוקסים.
- **`status` 200 בלבד על `path` אחד:** מעטפת סטטית, אין פנייה לנתונים.
- **`goto` שחוזר ב-18-19 ערכים בכל יום:** סורק עם רשימה קבועה.

## כיבוי מהיר

משתנה הסביבה `CRM_HIT_LOG=off` ב-Netlify מכבה את הרישום בלי דיפלוי (הפונקציה ממשיכה להעביר את הדף).

## הסרה

זמני. מסירים (קובץ הפונקציה ושורה זו) אחרי שהריצה זוהתה, או אחרי שבועיים בלי
ממצא. הפונקציה רצה על כל טעינת `/crm`, וכל הפעלה נספרת בחשבון ה-Netlify.
