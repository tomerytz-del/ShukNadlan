# ספק אריחי המפה

## מה קרה

באוגוסט 2026 **CARTO התחילו לדרוש מפתח API** לשירות האריחים הראסטריים שלהם
(`basemaps.cartocdn.com`). בקשה בלי מפתח לא נכשלת — היא מוחזרת כאריח תקין עם
הכיתוב **"API KEY REQUIRED"** חרוט עליו. המפה ממשיכה לזוז ולהתקרב, וכל המסך
מכוסה בהטבעה.

שום דבר בקוד של האתר לא השתנה. **הספק שינה תנאים מתחת לאתר חי.**

## למה חלק מהמפות נשארו תקינות

באתר חמש מפות, וכל אחת החזיקה את כתובת שרת האריחים שלה בעצמה:

| מפה | קובץ | הספק שהיה |
|---|---|---|
| דף הבית | `index.html` | הועברה ל-OpenStreetMap ← **תקינה** |
| משרדי תיווך על המפה | `agencies.html` | OpenStreetMap ← **תקינה** |
| דף הנכס | `property.html` | CARTO ← **מוטבעת** |
| מפת התכנון | `crm.html` | CARTO ← **מוטבעת** |
| עורך גבולות שכונות | `neighborhood-boundary.html` | CARTO ← **מוטבעת** |

כשהבעיה התגלתה, המפה בדף הבית תוקנה: נוסה מעבר ל-MapTiler (המפתח לא אומת
כמצופה), ואז היא הועברה לאריחי OpenStreetMap הציבוריים, שאינם דורשים מפתח.
התיקון נעשה בתוך `index.html` בלבד — ושלוש המפות האחרות נשארו מאחור. אף אחד
לא שם לב, כי לא היה מקום אחד להסתכל בו.

זו הסיבה האמיתית: לא בחירת ספק גרועה, אלא **חמישה עותקים של אותה החלטה**.

## מה תוקן

כל חמש המפות עברו ל-`assets/map-tiles.js` — קובץ אחד שמחזיק את הספק, את
כתובת האריחים, את הקרדיטים ואת הזום המרבי. שינוי ספק הוא מעכשיו שינוי
בקובץ אחד, ואי אפשר יותר לתקן מפה אחת ולשכוח ארבע.

```js
MapTiles.addTo(map);                  // ברירת המחדל
MapTiles.addTo(map, { maxZoom:20 });  // מפה שמתקרבת מעבר לזום הטבעי של הספק
```

`maxNativeZoom` נקבע לפי הספק, ולכן מפה שמבקשת זום 20 מול שרת שנעצר ב-19
מותחת את האריח האחרון במקום להציג ריבועים ריקים.

## מה צריך לעשות עכשיו (5 דקות)

כרגע כל המפות רצות על שרת האריחים הציבורי של OpenStreetMap. **זה עובד, אבל
זו נפילה־לאחור ולא היעד** — מדיניות השימוש של OSMF מייעדת את השרת ההוא
לתעבורה צנועה ולא לשירות מסחרי, והם חוסמים דומיינים שחורגים ממנה. אתר
מרקטפלייס עם חמש מפות הוא בדיוק המקרה שהמדיניות מכוונת אליו.

1. בקשו מפתח ב-<https://carto.com/basemaps/apikey/> — חינם, בלי חשבון ובלי
   תור אישור, מגיע במייל.
2. הדביקו אותו ב-`assets/map-tiles.js`:
   ```js
   var CARTO_KEY = 'המפתח-שהגיע-במייל';
   ```
3. זהו. כל חמש המפות חוזרות למראה ה-Voyager הבהיר, בלי הטבעה.

המכסה החינמית היא **5 מיליון בקשות אריח בחודש** — סדר גודל אחר לגמרי ממה
שהאתר צורך.

המפתח גלוי בקוד הדף, וזה תקין: מפתח בסיסמפ נועד להיות ציבורי, בדיוק כמו
המפתח הציבורי של Supabase שכבר יושב בכל דף. ההגנה עליו היא הגבלת דומיין
בצד CARTO, לא הסתרה.

## לטווח ארוך

CARTO מוציאים בהדרגה את האריחים הראסטריים לטובת וקטוריים. כשזה יקרה:

- **OpenFreeMap** — וקטורי, בלי מפתח, בלי מגבלת בקשות, מותר מסחרית. דורש
  MapLibre GL (אפשר להישאר על Leaflet דרך `maplibre-gl-leaflet`). זו האפשרות
  שלא תלויה באף ספק שיכול לשנות תנאים.
- **MapTiler** — מפתח, מכסה חינמית, ידידותי מסחרית. שימו לב להוסיף את
  הדומיין לרשימת המקורות המורשים במפתח — זו כנראה הסיבה שהניסיון הקודם
  "לא אומת כמצופה".
- **אחסון עצמי (Protomaps / PMTiles)** — הכי עמיד, הכי הרבה תחזוקה.

כל אחת מהן היא שינוי ב-`assets/map-tiles.js` בלבד.
