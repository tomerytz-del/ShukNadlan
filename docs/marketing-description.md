# תיאור שיווקי לנכס

כל נכס שנכנס לפלטפורמה מקבל תיאור שיווקי שנכתב מהנתונים שהסוכן/ת הזין/ה —
בלי שאיש יזכור ללחוץ על כפתור, ובלי שערוץ פרסום כלשהו יהיה מחובר.

## הבעיה שזה פותר

התיאור השיווקי כבר נכתב אוטומטית לפני הקובץ הזה — אבל **רק כתוצר לוואי של
הפוסט בפייסבוק** (`docs/facebook-auto-publish.md`). לצימוד הזה היו ארבעה
חורים, וכולם שקטים:

| מה קרה | למה |
|---|---|
| בלי ערוץ פרסום מחובר — אין תיאורים בכלל | `property-marketing-publish` מחזירה `publish_not_configured` **לפני** שהיא מגיעה לכתיבת הטקסט |
| ‏61 הנכסים שהיו בפלטפורמה לא קיבלו תיאור לעולם | הם נכנסו לתור הפרסום כ-`skipped`, כדי לא להציף את דף הפייסבוק ב-61 פוסטים |
| נכס שהמחיר או השטח שלו השתנו נשאר עם טקסט של אתמול | שורת הפרסום היא `unique` לכל החיים, ואחרי `posted` הנכס יוצא מהתור |
| לסוכן/ת לא הייתה דרך לבקש נוסח חדש | ‏`force` היה קיים — למנהל/ת פלטפורמה בלבד, ורק דרך פרסום חוזר לפייסבוק |

מכאן התיאור השיווקי הוא מנגנון בפני עצמו. הפוסט בפייסבוק צורך אותו, ולא
להפך.

## שני מסלולים

```
                       נכס נשמר
                          │
        ┌─────────────────┴─────────────────┐
        │ אין תיאור שיווקי                   │ יש תיאור שיווקי
        ▼                                   ▼
  טריגר → property_description_jobs    טביעת האצבע נשמרת על הנכס
        │  (pending, +10 דקות)               │
        │                                    │  נתוני הנכס משתנים מאוחר יותר
        │  pg_cron כל 5 דקות                  ▼
        ▼                             marketing_description_stale = true
  claim → Claude → apply                      │
        │                                     ▼
        ▼                            ה-CRM מציע "♻️ רענון תיאור"
  נשמר על properties                          │
  ‏source = ai                                 ▼
  התראה לסוכן/ת                    הסוכן/ת קורא/ת, עורך/ת ושומר/ת
                                    ‏source = agent
```

### המסלול האוטומטי

נכס פעיל שנשמר בלי `marketing_description` נכנס לתור. כעבור עשר דקות
(‏`marketing_description_delay_minutes`) ‏`pg_cron` מעיר את
`property-description`, ‏Claude כותב תיאור ופוסט קצר מהנתונים, והם נשמרים על
`properties` — כלומר זמינים מיד לדף הנכס, ל-CRM, לפוסט בפייסבוק ולכל ערוץ
שיתווסף אחר כך. הסוכן/ת מקבל/ת התראה בפעמון.

עשר הדקות הן חלון לתקן מחיר או שטח שהוקלדו שגוי בשמירה הראשונה. הן קצרות
מ-20 הדקות של הפוסט בפייסבוק בכוונה: פוסט אי אפשר לתקן בדיעבד בלי לאבד את
התגובות, וטקסט על הנכס אפשר לרענן בלחיצה.

### מסלול הרענון

כשנתוני הנכס משתנים אחרי שהתיאור נכתב, הנכס מסומן
`marketing_description_stale`, וב-CRM מופיעים תגית `♻️ כדאי לרענן תיאור`
וכפתור. הכפתור **מציע** נוסח — הוא לא שומר כלום. הסוכן/ת קורא/ת, עורך/ת
במקום, ורק אז שומר/ת.

אותו כפתור קיים גם בטופס עריכת הנכס, מתחת לשדה התיאור השיווקי.

## מה לא קורה כאן לעולם

**המסלול האוטומטי לא דורס טקסט שנכתב ביד.** זה לא תנאי בשרת שאפשר לשכוח
בגרסה הבאה, אלא התנאי שדרכו התור מדבר — `pending_property_descriptions`
מחזירה אך ורק נכסים ש-`marketing_description` שלהם ריק:

```sql
and nullif(btrim(coalesce(p.marketing_description, '')), '') is null
```

כל מסלול אוטומטי, קיים או עתידי, עובר דרך השאילתה הזו. גם באג בשרת לא יכול
למחוק נוסח של אדם.

**גם `post_text` לא נדרס.** ‏`apply_property_marketing_description` כותבת
פוסט חדש רק כשהשדה ריק. המערכת משלימה מה שחסר, לא מחליפה מה שנכתב ביד.

## למה טביעת אצבע ולא `updated_at`

"הנתונים השתנו" נמדד מול `md5` של השדות שבאמת נכנסים לטקסט — כותרת, תיאור
המודעה, סוג, מחיר, חדרים, שטחים, קומה, מיקום, מאפיינים, מצב, ריהוט, תאריך
כניסה והמידע התכנוני. העלאת תמונה, הקפצה, קידום או פתיחה לשת״פ משנים את
`updated_at` ולא את מה שיש לכתוב על הנכס.

בלי ההבחנה הזו כל נכס בפלטפורמה היה מסומן "מומלץ לרענן" תוך יום, וההצעה
הייתה מאבדת כל משמעות.

‏`features` ממוינים לפני ה-hash: סימון מחדש של אותם מאפיינים בסדר אחר אינו
שינוי תוכן.

## מי כתב את הטקסט

`marketing_description_source` מחזיק `agent` או `ai`, ומוחזק בטריגר
(‏`properties_track_marketing_copy`) ולא בקוד הקורא — התיאור נכתב היום משלושה
מקומות (טופס ה-CRM, אשף הייבוא, השרת), ושכחה של אחד מהם הייתה משאירה
מטא-דאטה שקרית שאיש לא בודק עד שהיא כבר שגויה.

הכלל: **ברירת המחדל היא "אדם".** ‏`ai` נרשם רק כשהשמירה עברה דרך
`apply_property_marketing_description`, שפתוחה ל-`service_role` בלבד ומדליקה
לשם כך משתנה סשן. לכן גם טקסט שהמערכת הציעה ושהסוכן/ת שמר/ה מהחלון ב-CRM
נרשם על שמו/ה — מי שקרא/ה, ערך/ה ואישר/ה מודעה אחראי/ת לה.

## הפרמטרים העסקיים

כולם ב-`pricing_config`, כמו כל מספר עסקי בפרויקט:

| מפתח | ברירת מחדל | מה זה |
| --- | --- | --- |
| `marketing_description_auto_enabled` | 1 | מתג הכיבוי. `0` עוצר את הכתיבה האוטומטית מיד |
| `marketing_description_delay_minutes` | 10 | כמה ממתינים משמירת הנכס |
| `marketing_description_daily_cap` | 80 | תקרת כתיבות ליממה — הגנת עלות מול Anthropic |
| `marketing_description_max_attempts` | 4 | ניסיונות לפני `failed` (‏15 דקות בין ניסיונות) |
| `marketing_description_manual_cooldown_seconds` | 45 | המתנה מזערית בין שתי בקשות רענון לאותו נכס |

```sql
-- לעצור את הכתיבה האוטומטית עכשיו (הרענון הידני ממשיך לעבוד)
update pricing_config set value = 0 where key = 'marketing_description_auto_enabled';
```

## הפרומפט

יושב ב-`supabase/functions/_shared/marketing-copy.ts`, ומשותף למסלול הזה
ולפוסט בפייסבוק — כך ששני המסלולים כותבים אותו דבר בדיוק, ותיקון בנוסח לא
צריך להיזכר פעמיים.

המגבלה החשובה בו היא **"רק מה שכתוב"**: מודל שממציא "קרוב לפארק" על נכס שלא
נאמר עליו דבר יוצר מודעה שקרית, וזו חשיפה משפטית של הפלטפורמה — לא רק טקסט
פחות טוב. באותה שורה: אין הבטחות תשואה, אין הצהרות על מגמות מחירים, ואין
אזכור של מוצא, דת, לאום או הרכב משפחתי.

## הרשאות

| מי | מה מותר |
| --- | --- |
| ‏`pg_cron` / `service_role` | ריקון התור, כתיבה ושמירה על כל נכס |
| סוכן/ת מחובר/ת | בקשת נוסח לנכס שלו/ה או של המשרד. ההרשאה וה-cooldown נבדקים ב-`request_property_description` במסד, בהקשר ה-JWT — לא בשרת |
| מנהל/ת פלטפורמה | כל נכס, וקריאת יומן התור |
| גולש/ת אנונימי/ת | כלום |

ההרשאה רחבה מזו של `bump_property` בכוונה: גם שותפ/ה במשרד רשאי/ת. עריכת
הנכס פתוחה לאותו מעגל ממילא, וטקסט שיווקי הוא פעולה חלשה יותר מעריכת מחיר.

## הנכסים שכבר היו בפלטפורמה

כאן ההפך ממיגרציית הפרסום. שם הנכסים הקיימים נכנסו כ-`skipped`, כי 61 פוסטים
ברצף הם הצפה של דף הפייסבוק. תיאור שיווקי אינו מתפרסם לשום מקום ברעש — הוא
נשמר על המודעה — ולכן דווקא הנכסים הוותיקים הם מי שהכי צריך אותו: הם אלה
שהמנגנון הישן דילג עליהם.

המיגרציה עושה שני דברים:

1. **קו בסיס** ל-51 הנכסים שכבר יש להם תיאור: טביעת האצבע נשמרת כפי שהיא
   עכשיו, כדי שאף אחד מהם לא יסומן "מומלץ לרענן" ברגע ההתקנה. המקור נקרא
   מיומן הפרסום — נכס שסומן שם `description_generated` הוא נוסח של Claude,
   וכל השאר, עד שיוכח אחרת, נוסח של אדם.
2. **תור** ל-10 הנכסים הפעילים שאין להם תיאור, מפוזרים דקה זה מזה כדי שלא
   ייצא מהם עומס אחד על Anthropic.

## בדיקה ידנית

```bash
# ריקון התור עכשיו, בלי להמתין ל-cron
curl -X POST "$SUPABASE_URL/functions/v1/property-description" \
  -H "Authorization: Bearer $SERVICE_ROLE_KEY"

# נוסח לנכס מסוים, בלי לשמור
curl -X POST "$SUPABASE_URL/functions/v1/property-description" \
  -H "Authorization: Bearer $SERVICE_ROLE_KEY" -H "Content-Type: application/json" \
  -d '{"property_id":"<uuid>","mode":"preview"}'

# נוסח לנכס מסוים — ושמירה (דורס תיאור קיים)
curl -X POST "$SUPABASE_URL/functions/v1/property-description" \
  -H "Authorization: Bearer $SERVICE_ROLE_KEY" -H "Content-Type: application/json" \
  -d '{"property_id":"<uuid>","mode":"apply"}'
```

```sql
-- מה בתור ומה נתקע
select j.status, j.reason, j.attempts, j.last_error, p.title
  from property_description_jobs j
  join properties p on p.id = j.property_id
 order by j.updated_at desc limit 20;

-- נכסים פעילים שאין להם תיאור שיווקי
select listing_number, title from properties
 where status = 'active'
   and nullif(btrim(coalesce(marketing_description, '')), '') is null;

-- נכסים שהנתונים שלהם השתנו מאז שהתיאור נכתב
select listing_number, title, marketing_description_source, marketing_description_at
  from properties where marketing_description_stale;

-- החזרת נכס לתור ידנית
select queue_property_description('<uuid>', 'manual', true, 0);
```

## תקלות אפשריות

| מה רואים | מה זה |
| --- | --- |
| `copy_not_configured` (503) | ‏`ANTHROPIC_API_KEY` לא מוגדר ב-Edge Functions → Secrets. התור לא נשרף — השורות ממתינות |
| `cron_secret_not_configured` (503) | ‏`ALERT_CRON_SECRET` חסר. חוסם רק את המסלול האוטומטי; רענון של סוכן/ת עובד |
| `cooldown_active` (429) | לחיצה חוזרת תוך פחות מ-45 שניות על אותו נכס |
| נכס נשאר בלי תיאור והתור ריק | ‏`marketing_description_auto_enabled = 0`, או שהתקרה היומית נגמרה — השורות ימשיכו מחר |
| שורה ב-`failed` | ארבעה ניסיונות נכשלו. ‏`last_error` אומר למה; `queue_property_description(..., true)` מחזיר לתור |
