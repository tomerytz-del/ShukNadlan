# עסקאות לפי יישוב - הסוכן שמושך מ-GovMap, ודפי ‏`/deals`

שלושה חלקים שעובדים יחד:

1. **רשימת יישובים** במסד (‏`deal_settlements`), שמנוהלת במסך "יישובים
   לעסקאות" ב-CRM.
2. **סוכן דפדפן** (Claude in Chrome) שעובר על היישובים הפעילים, מושך את
   העסקאות מ-GovMap וכותב אותן דרך `upsert_deals()`.
3. **דף ציבורי לכל יישוב** - ‏`/deals/afula` - ואינדקס ב-`/deals`.

> **מ-9.10.2026 הסוכן הוא הדרך שבה עסקאות נכנסות.** ההדבקה הידנית
> (מסך "מצב העסקאות" ב-CRM) נשארת מקופלת, כגיבוי בלבד - למשל כש-GovMap
> חוסם את הסוכן.

> **אין כאן scraper ואין קריאה ל-API של GovMap.** ה-API דורש reCAPTCHA,
> ו-nadlan.gov.il חוסם שליפה תוכניתית (‏`docs/market-deals-official.md`,
> "למה הצינור מנותק"). הסוכן עובד בדפדפן של מנהל/ת הפלטפורמה, כמו אדם.

## למה לא טבלת עסקאות חדשה

המפרט המקורי נכתב לפרויקט הישן (‏`nadlan-afula`) וביקש טבלה חדשה,
‏`real_estate_deals`, עם קריאה ציבורית. כאן כבר יש טבלה לזה בדיוק:
‏**`market_deals_official`**. היא מחזיקה כ-30 אלף עסקאות ב-29 יישובים,
שכולן הודבקו מ-GovMap, ומזינה את דוח ה-CMA ואת `/prices`.

| | מה היה קורה עם טבלה שנייה |
| --- | --- |
| דוח ה-CMA | לא היה רואה את מה שהסוכן מושך |
| ‏`/prices` | אותו דבר |
| כפילויות | אותה עסקה בשתי טבלאות, עם שני מפתחות שונים |
| פרטיות | גוש, חלקה ומספר בית פתוחים ל-anon, והטבלה הקיימת סגורה בכוונה |

לכן הסוכן כותב ל-`market_deals_official`, עם **אותו `external_key`
שההדבקה בונה**. עסקה שכבר הודבקה ביד אינה נכנסת פעמיים, וזה נבדק:
שורה עם `"area_sqm": "134.0"` ו-`"price": "1,495,000 ₪"` נפלה על המפתח
`govmap:17014-9-77:2026-08-31:1495000:134` של שורה שהודבקה.

**"ייבוא הנתונים הקיימים"** (‏`scripts/import-legacy-deals.js` במפרט) לא
נכתב, כי אין מה לייבא: הנתונים הקיימים כבר בטבלה הנכונה. מה שכן נעשה
הוא החלק השני של אותו סעיף - כל יישוב שיש לו עסקאות במאגר נכנס ל-
`deal_settlements` במיגרציה, עם `slug` מ-`cities` (לפי `city_name_key`,
כי "נהרייה" במאגר היא "נהריה" ב-`cities`) או מתעתיק כשאין.

### ההרשאות: למה authenticated ולא service_role בלבד

המפרט ביקש `revoke` מ-anon **ומ-authenticated**. אבל הסוכן רץ בדפדפן,
ובדפדפן אין, ואסור שיהיה, מפתח `service_role` - הוא עוקף את כל ה-RLS
באתר. לכן הפונקציות פתוחות ל-`authenticated` עם גידור פנימי ב-
`current_is_platform_admin()`, כמו `market_deals_import`. משתמש/ת מחובר/ת
שאינו/ה מנהל/ת מקבל/ת `{"error":"forbidden"}`.

### ‏`upsert_deals`

```js
await sb.rpc('upsert_deals', {
  p_settlement: 'עפולה',
  p_rows: [{
    address: 'הנביאים 12',        // "אין מידע" או ריק -> null
    neighborhood: 'גבעת המורה',   // אופציונלי
    gush: '17014', helka: '9', tat_helka: '77',  // או gush_helka: '17014-9-77'
    deal_date: '31.08.2026',      // או 2026-08-31
    property_type: 'דירה',        // "-" -> null
    rooms: '4', floor: 'שלישית', area_sqm: '134', price: '1,495,000'
  }]
})
// -> { added, updated, unchanged, rejected: [{row, reason}], rejected_count }
```

- **הנרמול במסד**, לא אצל הסוכן: תווי כיווניות (‏`קומה ‎3‏`), פסיקים
  ו-₪, ‏"אין מידע", ‏"-", ופיצול הכתובת לרחוב ולמספר בית.
- **עדכון ולא התעלמות** - שורה קיימת מתעדכנת כשהסוכן מביא כתובת, שכונה,
  סוג, חדרים או קומה שלא היו. ערך ריק מהסוכן **אינו מוחק** ערך קיים.
  ‏`updated_at` זז רק כשמשהו השתנה בפועל.
- **מחיר ומ"ר אינם מתעדכנים** - הם חלק מהמפתח. שתי עסקאות באותה תת-חלקה
  ובאותו יום נבדלות רק בהם (‏`market-deals-official.md`, ‏"‏`external_key`").
- **שורה פגומה נספרת ומוחזרת**, ואינה מפילה את השאר.
- כל קריאה נרשמת ב-`market_deal_import_runs`, ו-`deal_settlements` מקבלת
  `last_synced_at`, ‏`last_status`, ‏`deals_added`, ‏`deals_updated`.
- ‏`raw.ingest = 'browser_agent'` (ההדבקה: `manual_paste`). ‏`source`
  נשאר `tax_authority` מאותה סיבה כמו בהדבקה.

### ‏`deal_sync_plan(p_limit = 25)` (מיגרציה `20270330090000`)

מחזירה **רק יישובים שהגיע תורם**, ועד `p_limit` מהם:

```
{ name, sync_from, last_synced_at, due_total }
```

- **‏`sync_from`** - ‏90 יום לפני העסקה האחרונה ביישוב, ולא ממנה, כי רשות
  המסים מדווחת באיחור. ביישוב בלי עסקאות: `months_back` חודשים אחורה.
  החפיפה זולה - היא חוזרת כ-`unchanged`.
- **‏`due_total`** - כמה ממתינים בסך הכול. הסוכן ממשיך למנה הבאה עד 0.

## מחזור העדכון

| | |
| --- | --- |
| **מי ברשימה** | כל עיר פעילה בשוק (‏`cities.market_slug`). ‏`deal_settlements_sync_cities()` רצה במיגרציה ומטריגר על `cities`: עיר שמצטרפת לשוק מצטרפת גם לכאן |
| **מתי מגיע תורו** | יישוב פעיל ש-`last_synced_at` שלו ריק או ישן מ-`sync_every_days` (ברירת מחדל 30 יום - רשות המסים מפרסמת בקצב חודשי) |
| **הסדר** | מי שלא נוסה מעולם, ואז הניסיון הכי ישן (‏`last_attempt_at`); בתוך זה הגדולים קודם (אוכלוסייה) |
| **כישלון** | ‏`deal_sync_fail` מסמן `last_attempt_at`, והיישוב יורד לסוף התור - תקלה אחת לא חוסמת את המנה |
| **יישוב בלי עסקאות ב-GovMap** | ‏`upsert_deals(name, [])` - נרשם כעדכון מוצלח, וחוזר רק בעוד מחזור |
| **מי שם לב שהמחזור עומד** | הסוכן התפעולי: `deal_sync_stopped` (בינוני) כשאף יישוב לא עודכן 14 יום ויש ממתינים, `deal_sync_overdue` (נמוך) כשיישובים חורגים מהמחזור ב-14 יום ויותר. ‏`_deal_sync_cycle` ב-`ops_agent/probes/behavior.py` |

**למה הממצא ולא תזמון בשרת:** הסוכן רץ בדפדפן של מנהל/ת הפלטפורמה -
שם עובר ה-reCAPTCHA - ולכן אין workflow שיאדים כשהוא לא רץ. אם הסוכן
תומך במשימה מתוזמנת (‏Claude in Chrome: קיצור דרך עם תזמון), כדאי לתזמן
את "עדכן עסקאות" לפעם בשבוע; הממצא הוא מה שתופס את השבוע שבו זה לא קרה.

**דפים ריקים אינם נחשפים:** ‏`deal_settlements_public()` - האינדקס וה-
sitemap - מחזירה רק יישובים עם עסקאות, ודף יישוב עם פחות מ-5 עסקאות
יוצא עם `noindex`. אחרת 214 הכפרים ברשימה היו מאות דפים דלים בגוגל.

## הסוכן: "עדכן עסקאות"

הכפתור "העתק פקודת עדכון" במסך מעתיק את המשפט `עדכן עסקאות`. **המשפט
לבדו אינו אומר לסוכן דבר** - ההוראות למטה הן מה שצריך לשמור אצלו (קיצור
דרך, או ההוראה הקבועה שלו), והמשפט רק מפעיל אותן:

```text
כשאני כותב "עדכן עסקאות":

1. פתח לשונית https://shuknadlan.co.il/crm (אני מחובר כמנהל הפלטפורמה).
   המשתנה sb גלובלי בדף - הרץ דרכו בקונסול.
2. const { data: plan, error } = await sb.rpc('deal_sync_plan', { p_limit: 25 })
   אם error או plan ריק - דווח "אין יישובים ממתינים" וסיים.
3. לכל שורה ב-plan (name, sync_from):
   א. ב-https://www.govmap.gov.il חפש את היישוב name, ופתח את לשונית "עסקאות נדל״ן".
   ב. קרא את השורות מהחדשה לישנה, עד התאריך sync_from (כולל). לכל עסקה:
      { address, neighborhood, gush_helka: "גוש-חלקה-תת", deal_date: "DD.MM.YYYY",
        property_type, rooms, floor, area_sqm, price }
      בדיוק כפי שהם מוצגים - בלי לנקות ובלי לתרגם. "אין מידע" ו-"-" נשארים כמו שהם.
   ג. await sb.rpc('upsert_deals', { p_settlement: name, p_rows: rows })
      במנות של עד 500. גם כשאין אף עסקה - קרא עם p_rows: [] (כך היישוב נרשם כמעודכן).
   ד. אם משהו נכשל (reCAPTCHA שלא עבר, היישוב לא נמצא, הטבלה לא נטענה):
      await sb.rpc('deal_sync_fail', { p_settlement: name, p_error: '<מה קרה>' })
      ועבור ליישוב הבא. אל תנחש נתונים.
4. אם due_total בשורה הראשונה של plan גדול ממספר היישובים שעברת - חזור לשלב 2.
5. בסוף: טבלה - יישוב, added, updated, rejected_count, או השגיאה.
```

**התקרה של GovMap:** 1,500 העסקאות האחרונות ליישוב
(‏`market-deals-official.md`). מה שלפניהן אינו זמין משם.

**‏`name` הוא השם ב-GovMap**, והוא גם `market_deals_official.city`.
‏`/prices` מצטרף ל-`cities` לפי שם מדויק, ולכן יישוב שנכתב אחרת שם
(‏"נהרייה" מול "נהריה") מופיע ב-`/deals` ולא ב-`/prices`. זה מצב קיים
של ההדבקה, לא של הסוכן.

### מה בדף יישוב

- כותרת: "עסקאות נדל״ן ב{יישוב} - {חודש ושנה}" (העדכון האחרון).
  מקף רגיל ולא ארוך - הכלל של האתר.
- שלושה כרטיסים: עסקאות ב-12 חודשים, מחיר חציוני, מחיר חציוני למ"ר.
- חציון לפי חדרים: עד 3, ‏4, ‏5, ‏5.5 ומעלה. קבוצה מתחת ל-5 עסקאות
  מושתקת **במסד**.
- 60 העסקאות האחרונות, עם מיון בכותרות ובתיבת בחירה. בטלפון הטבלה הופכת
  לכרטיסים.
- "מקור: רשות המסים, דרך GovMap".
- ‏JSON-LD: ‏`Dataset` ו-`BreadcrumbList`.

**מגורים בלבד**: בלי 'בנין', 'קרקע' ו'משק חקלאי', ‏25-400 מ"ר, ‏200 אלף
עד 15 מיליון ₪. בניגוד ל-`/prices`, קוטג' ובית נכללים - ביישוב קטן הם רוב
השוק. **12 חודשים מהעסקה האחרונה ביישוב**, לא מהיום.

**פרטיות**: רחוב ושכונה, בלי מספר בית, גוש וחלקה
(‏`docs/property-address-privacy.md`). הפונקציה פשוט לא מחזירה אותם.

### ‏canonical, ולמה הוא נקבע מהכתובת

‏`deals.html` נושא canonical סטטי אחד - `/deals` - כי הוא גם האינדקס.
דף יישוב מקבל את שלו מ-`deals-page.ts`, **מה-slug שבכתובת ולפני הקריאה
למסד**. אילו זה היה תלוי בתשובת המסד, דקה של Supabase איטי הייתה מאחדת
את כל היישובים לאינדקס - בדיוק הסכנה שבגללה לדפי פירוט אסור לשאת
canonical סטטי (‏`scripts/check_canonical.py`). ‏`noindex` נכנס רק כשהמסד
ענה במפורש שאין יישוב כזה.

### ‏`<base href="/">`

הדף מוגש גם תחת `/deals/afula`, ושם `assets/x.js` יחסי היה נפתר ל-
`/deals/assets/x.js`. ה-`base` יושב מיד אחרי קטע ה-GTM, לפני כל כתובת
יחסית, וכך שאר הדף נשאר זהה לשאר האתר (והבדיקות שמחפשות
`src="assets/events.js"` עוברות).

### ‏"טריגר build אחרי עדכון" - לא נדרש

אין build. הדף מתמלא בשרת בכל בקשה ונשמר במטמון של Netlify לשעה; דף
שלא מולא אינו נשמר. כלומר עד שעה אחרי ש-`upsert_deals` רצה, הדף מעודכן.

### ‏sitemap

‏`/deals` ב-`sitemap.xml`; היישובים הפעילים **שיש להם עסקאות** מ-
`sitemap.ts`, מקור "עסקאות לפי יישוב" - דרך `rpc/deal_settlements_public`
ולא ישירות מהטבלה, שמחזיקה גם את כל הכפרים בלי עסקאות - בצורת נתיב
(‏`path`) ולא `?slug=`.

## הבדיקה שנעשתה

המיגרציה הורצה פעמיים על Postgres 16 מקומי עם תחליפים ל-`auth.role()`
ול-`current_is_platform_admin()`:

| מה | תוצאה |
| --- | --- |
| הרצה ראשונה, 3 שורות טובות ו-2 פגומות | ‏`added 2, updated 1, rejected 2` (ה-updated היא השורה שכבר הודבקה) |
| אותה הרצה שוב | ‏`added 0, updated 0, unchanged 3` |
| שורה עם כתובת שהייתה "אין מידע" | ‏`updated 1` - הכתובת הושלמה |
| anon: ‏`upsert_deals`, ‏`deal_sync_plan`, ‏`insert`/`update` ל-`deal_settlements`, ‏`select` מ-`market_deals_official` | ‏`permission denied` |
| מחובר/ת שאינו/ה מנהל/ת | ‏`forbidden`, ועדכון לטבלה עובר על 0 שורות (RLS) |
| ‏service_role | עובר |

על הפרודקשן לא נכתבה שורה: DDL רק דרך הצינור (‏`CLAUDE.md`), ולכן
הבדיקה על המסד האמיתי היא אחרי המיזוג - ראו "אחרי המיזוג".

## אחרי המיזוג

1. מבט ב-**Actions**: ‏`supabase_migrations.yml` ירוק.
2. ב-CRM → "יישובים לעסקאות": עפולה ומגדל העמק שם, עם כ-30 היישובים
   שכבר יש להם עסקאות.
3. ‏`/deals/afula` ו-`/deals` נטענים עם מספרים.
4. הרצה ראשונה של "עדכן עסקאות" על יישוב אחד, ואז שוב - השנייה צריכה
   להחזיר `added: 0`.
