## 2. מטרות השימוש

1. ניהול עבודת תיווך למשרדים ולסוכנים/ות: נכסים, לקוחות, לידים, פגישות, הסכמים (CRM).
2. פרסום נכסים באתר וברשתות, וחיבור בין גולשים/ות למתווכים/ות.
3. בוטים בוואטסאפ: עוזר ציבורי לגולשים ועוזר אישי לסוכן/ת.
4. מעקב שיחות: מספרים וירטואליים, הקלטה, תמלול וסיכום.
5. חיוב, ארנק וחשבוניות.
6. אבטחה, תפעול ומדידה (ניטור, אימות כניסה, אנליטיקה ללא PII).

## 4. העברות מידע לספקים

הרשימה המלאה, מה כל ספק מקבל ומצב ה-DPA: **`docs/suppliers.md`**. בקצרה:
Supabase (הכל), Netlify, Meta, Twilio, Anthropic, OpenAI, Google, fal.ai,
Make, מורנינג, Resend, GovMap.

- חלק מהספקים מעבדים מידע **מחוץ לישראל** (ארה"ב / האיחוד האירופי). יש לבדוק
  עמידה בתקנות העברת מידע אל מאגרים שמחוץ לגבולות המדינה [למלא].
- **אף DPA לא אושר ותועד** (כל השורות "לבדוק / לחתום") - פער.
- מדיניות הפרטיות שמפרטת את הספקים: `privacy.html`.

## 6. הרשאות גישה לפי תפקיד

| תפקיד | גישה | איך נאכף |
| --- | --- | --- |
| גולש/ת (`anon`) | נכסים פעילים ותצוגות ציבוריות בלבד (`agency_members_public` וכו') | RLS והרשאות `anon`; סריקה ב-`ops_agent/probes/security.py` |
| סוכן/ת | הנכסים, הלקוחות, הלידים והשיחות של עצמו/ה; מה שהמשרד משתף | RLS לפי `auth.uid()`; ‏`leads_masked` לליד נעול |
| מנהל/ת משרד | נתוני המשרד, כולל שיחות המשרד בקריאה בלבד | `agency_members.role = 'manager'`; `20270222090000_office_calls.sql` |
| מנהל/ת פלטפורמה | כל המערכת | `is_platform_admin`; אימות דו-שלבי חובה (`docs/mfa.md`) |
| שירות (`service_role`) | Edge Functions ומנועים | סוד ב-Supabase/GitHub Secrets בלבד |
| הסוכן התפעולי | קריאה בלבד | `default_transaction_read_only` (`docs/ops-agent.md`) |

כל המשתמשים המחוברים יכולים להפעיל אימות דו-שלבי; לא נדרש לסוכנים רגילים (פער - R1).
