# יומן שיחות: מספר, הקלטה, תמלול וסיכום (פיילוט Twilio)

לקוח/ה מתקשר/ת למספר של Twilio שמשויך לסוכן/ת. השיחה מנותבת לנייד של
הסוכן/ת ומוקלטת, ובסופה הסוכן/ת מקבל/ת בוואטסאפ סיכום של השיחה ואת
ההקלטה, והשיחה נכנסת ליומן ב-CRM.

**למה דרך Twilio:** דפדפן אינו רואה את יומן השיחות של הטלפון בשום מכשיר
(`crm-contacts-import.md`), ולכן יומן אמיתי מחייב שהשיחה תעבור דרכנו.
ההשוואה מול Voicenter וההחלטה: Twilio מאפשרת להקצות מספרים מהקוד, בתשלום
לפי שימוש, ואת התמלול והסיכום אנחנו עושים בעצמנו בכל מקרה.

## הזרימה

```
לקוח/ה ──► מספר Twilio ──► twilio-voice?event=incoming
                              │  הודעת הקלטה (Google TTS, עברית)
                              │  <Dial record> לנייד של הסוכן/ת, callerId = המתקשר/ת
                              ▼
                        ?event=dial ── לא נענתה ──► "נחזור אליכם" + וואטסאפ לסוכן/ת
                              │
                        ?event=recording
                              │  הורדה ← דלי call-recordings ← מחיקה מ-Twilio
                              │  Whisper ← Claude (סיכום, שם, דרישות, צעד הבא)
                              ▼
                        וואטסאפ לסוכן/ת: סיכום + קובץ שמע · שורה ב-agent_calls
```

| רכיב | איפה |
| --- | --- |
| הפונקציה | `supabase/functions/twilio-voice/index.ts` (‏`verify_jwt = false`) |
| הטבלאות | `agent_phone_lines`, `agent_calls` - מיגרציה `20270202090000_call_tracking.sql` |
| ההקלטות | דלי פרטי `call-recordings/<agent_id>/<call_id>.mp3` |
| ה-CRM | בלוק "שיחות אחרונות" בקובץ הלקוחות (`loadCalls` ב-`crm.js`), עם עדכון כרטיס וסימולציה |
| העוזר | הכלי `list_calls` ב-`whatsapp-webhook/agent.ts` |
| המחיקה | cron יומי `call-recordings-cleanup` ← `twilio-voice?task=cleanup` |
| פרטיות | `privacy.html#calls` |

## ארבעה כללים

1. **כל וובהוק מאומת בחתימה.** ‏`X-Twilio-Signature` מחושבת על הכתובת
   **החיצונית** (`SUPABASE_URL/functions/v1/twilio-voice?...`) ולא על
   `req.url`, שבתוך ה-Edge Runtime אינה זהה. בלי `TWILIO_AUTH_TOKEN` הפונקציה
   עונה 503 ואינה מעבדת כלום.
2. **מספר בלי שורה פעילה ב-`agent_phone_lines` עונה בהודעה ומנתק.** הוא לעולם
   אינו "נופל" לסוכן/ת אחר/ת. אין ממשק הקצאה: בפיילוט השורה נכתבת במיגרציה.
3. **העותק היחיד של ההקלטה אצלנו, עם תאריך תפוגה אחד.** היא נמחקת מ-Twilio מיד
   אחרי ההעתקה, ומאיתנו אחרי **90 יום**. התמלול והסיכום נשארים בשורה.
   המחיקה עוברת דרך ה-Storage API ולא ב-SQL, כי מחיקת שורה מ-`storage.objects`
   משאירה את הקובץ עצמו יתום.
4. **בתוך חלון 24 השעות של וואטסאפ - טקסט ושמע; מחוצה לו - התבנית.** אותה
   תבנית של ההתראות (`WHATSAPP_NOTIFY_TEMPLATE`), עם הסיכום כשורה אחת וכפתור
   ל-CRM. תבנית אינה יכולה לשאת קובץ שמע, ולכן אז ההקלטה מחכה ב-CRM. קובץ מעל
   16MB אינו נשלח בוואטסאפ בכל מקרה.

## מהשיחה לכרטיס

הסיכום חוזר ב-**structured outputs** (`SUMMARY_SCHEMA`), כמו התיאור השיווקי:
בשיחה האמיתית הראשונה (4.10.2026) המודל הוסיף טקסט אחרי ה-JSON, והסוכן קיבל
"לא הצלחתי לסכם" על שיחה תקינה. כל שדה בסכימה נוכח, ו-null כשלא נאמר.

הסיכום מחזיר גם `needs` - הדרישות **בשמות השדות של `agent_clients`**
(`deal_type`, `cities`, `min_rooms`, `min_price`, `max_price`), רק מה שנאמר
במפורש, ומנוקה בקוד (‏`cleanNeeds`: טווחים סבירים, מינימום שאינו עולה על
המקסימום). משם שלוש דרכים להגיע לכרטיס:

| איפה | מה |
| --- | --- |
| ה-CRM, לקוח/ה מוכר/ת | "🔄 עדכון הכרטיס מהשיחה" - ערים **בתוספת** לקיימות, ו-`paused` עובר ל-`active` |
| ה-CRM, מספר לא מוכר | "➕ הוספה לקובץ" ממלא שם, טלפון **ודרישות** בטופס |
| וואטסאפ | "כן, תעדכן" / "כן, תוסיף" אחרי הסיכום ← `list_calls` ← `update_client` / `create_client` |

**ולמה ערים בתוספת:** לקוח/ה שאמר/ה בשיחה "גם בעפולה" לא ויתר/ה על נצרת
שכבר בכרטיס. החלפה הייתה מוחקת דרישה בלי שאיש אמר את זה.

## מספרים וירטואליים (מעקב): כינוי, מקור, הזמנה מהארנק, ומסלול

כל מספר הוא ערוץ: "שלט - האורנים 13", "יד2 - פנטהאוז", "פייסבוק - קמפיין אוקטובר". השיחות
כבר נשמרות עם `line_id`, ולכן הכינוי (`label`), המקור (`source_type`) והנכס (`property_id`)
הם מה שהופך אותן לדוח "מאיפה הלקוחות מגיעים". הכינוי מופיע גם בכל הודעה בוואטסאפ ("דרך: ...").

**ניהול המספרים ב-CRM** - בהגדרות החשבון, קטגוריה "מספרים וירטואליים" (`#accLines`); השיחות עצמן נשארו ב"שיחות אחרונות" בקובץ הלקוחות, עם קישור לשם: לכל מספר 30 הימים האחרונים - שיחות, נענו,
לא נענו, מתקשרים, מהקובץ, ונוספו לקובץ אחרי השיחה. עריכת הכינוי, הניתוב והמספר הקיים - `phone_line_set_details()`
(עמודות אלה בלבד, רק במספר שלך; אין policy של update שהייתה פותחת גם את המחיר והתוקף).

**הזמנה - 89 ₪ לחודש מהארנק** (`pricing_config.phone_line_monthly_price`):

| שלב | איפה |
| --- | --- |
| מספר פנוי בקידומת (קווי בלבד - לא נייד, ראו "04 ולא 053") | `twilio-voice?task=lines-available` |
| אישור וחיוב - אותו חלון של כל רכישה (`confirmPurchase`) | CRM |
| ניכוי + שורה `pending`, בטרנזקציה אחת | `order_phone_line()` - ל-service_role בלבד |
| קנייה ב-Twilio עם ה-Webhook כבר מוגדר | `twilio-voice?task=lines-order` |
| נכשלה - הכסף חוזר | `phone_line_order_failed()` |

**הסדר מכוון:** מחייבים ואז קונים. ההפך היה משאיר אצלנו מספרים קנויים של מי שאין לו/ה יתרה.

**חידוש:** cron יומי `phone-lines-renew` (‏04:23 UTC) ← `claim_due_phone_line_renewals()`. יש יתרה -
עוד חודש ושורה ב-`phone_line_charges`. אין - `payment_failed_at`, התראה בפעמון, והמספר **ממשיך
לעבוד 7 ימים** (שיחה שהולכת לאיבוד עולה יותר מ-89 ₪). אחרי 7 ימים - משוחרר ב-Twilio.
מספר בלי `monthly_price` (הפיילוט, או מספר שהפלטפורמה נתנה) אינו מחויב, ואינו מתבטל מה-CRM.

**לפי מסלול** (`phone_line_included_eligible` - ‏`premium` + `billing_status` + `active`):

| מסלול | מה מותר |
| --- | --- |
| Elite | מספר אחד **כלול** (`included`, מתחדש בלי חיוב) ונוספים ב-89 ₪, בלי תקרה |
| PROFESSIONAL, Pay&GO | מספר אחד ב-89 ₪. מספר שני - `order_phone_line` מחזירה `tier_required` |

בתצוגה: הכפתור אינו מוסתר אלא אומר "מספרים וירטואליים נוספים - במסלול Elite" עם קישור לשדרוג,
ומי שעוד אין לו/ה מספר רואה שב-Elite הראשון כלול. אחרי קנייה ב-Elite, חלון האישור מסביר מה קורה
בירידת מסלול, ודורש סימון שזה נקרא.

**ירידה מ-Elite** - `phone_line_tier_sweep()`, בכל הרצה של ה-cron, **לפני** החידוש. סבב שבודק את
המצב ולא טריגר על `agency_members`, כי המסלול יורד בחמש דרכים שונות (פקיעה, מנהל/ת, סוף הטבה,
בחירה, סגירת חשבון) והסבב תופס את כולן:

| מצב | מה קורה |
| --- | --- |
| Elite שמסתיים בעוד 7 ימים (`paid_tier_until` / `promo_ends_at`), ויש מספר כלול או כמה | התראה מראש (`downgrade_warned_at`, פעם ב-20 יום) |
| ירד/ה, מספר אחד כלול | עובר לתשלום - 89 ₪ מסוף התקופה שכבר כוסתה |
| ירד/ה, כמה מספרים | `downgrade_deadline` = עוד 7 ימים, והתראה. ב-CRM "להשאיר את המספר הזה" (`phone_line_keep_on_downgrade`) |
| נגמר החלון | נשאר הנבחר, או זה שקיבל הכי הרבה שיחות ב-30 יום, או הוותיק; השאר משתחררים ב-Twilio |
| חזר/ה ל-Elite בתוך החלון | החלון מתבטל |
| Elite בלי מספר כלול (שדרוג, או מספר שנקנה לפני הכלל) | הוותיק נעשה כלול |

**לאן לנתב** (`forward_to`) - בכל מספר, מחלון העריכה: נייד שני, מזכירות, שותף/ה. ריק = הנייד
הרשום. מספר ישראלי בלבד (נבדק במסד וב-Edge): ניתוב לחו"ל היה עולה לנו כסף בלי תקרה.

**מספר קיים של הסוכן/ת** (`external_number`) - מספר שכבר מפורסם (וירטואלי אצל ספק אחר, קו של
המשרד, נייד). הוא מתחבר ב**הפניית שיחות** אצל הספק שלו אל מספר שלנו, ולכן כל מספר קיים צריך
מספר משלו אצלנו: שיחה מופנית מגיעה ל-Twilio עם `To` = המספר שלנו, ורק לפיו אפשר לדעת מאיזה ערוץ
היא הגיעה. השדה נשמר לתצוגה ולהוראות ("איך מפנים?": בנייד `**21*<המספר שלנו>#`, ביטול `##21#`;
בספק וירטואלי - באפליקציה שלו). העברת המספר עצמו (ניוד) ל-Twilio אינה אפשרית בישראל.

**ביטול** - `task=lines-release`: המספר משוחרר ב-Twilio מיד, בלי החזר על יתרת החודש. השיחות
וההקלטות נשארות.

**העלות שלנו** (מחירון Twilio לישראל, 10.2026): ‏$5.5 לחודש למספר 04, ולדקה שנענתה:

| רכיב | לדקה |
| --- | --- |
| קבלה במספר קווי | $0.0107 |
| הרגל לנייד, caller ID ישראלי | $0.0646 (‏$0.0294 לקו נייח) |
| הרגל לנייד, כל caller ID אחר | **$0.1868** |
| הקלטה + Whisper | $0.0085 |

כ-31 אגורות לדקה, ועוד כ-5 אגורות לסיכום. **‏89 ₪ הם לפני מע"מ**, כמו כל מחיר בדף המסלולים, ולכן
נקודת האיזון מולם (אחרי $5.5 של המספר) היא כ-220 דקות בחודש למספר. לכן:

**150 דקות בחודש למספר, ומעבר לזה 0.5 ₪ לדקה מהארנק** (`pricing_config`:
`phone_line_included_minutes`, `phone_line_overage_per_min`). גם למספר הכלול ב-Elite.

| | איפה |
| --- | --- |
| דקה = כל דקה שהתחילה בשיחה שנענתה (`ceil`), חודש קלנדרי בשעון ישראל | `charge_call_minutes()` מ-`onDial`, אידמפוטנטית (`billed_minutes`), נועלת את שורת המספר |
| מעבר לתקרה - ניכוי ושורה `overage` ב-`phone_line_charges` | אותה פונקציה |
| אין יתרה - השיחה **עוברת**, בלי הקלטה ובלי ההודעה שהיא מוקלטת | `phone_line_recording_allowed()` ב-`onIncoming` |
| התראות: 80%, הגעה לתקרה, ודקות שלא כוסו (פעם ביום) | `chargeMinutes` - פעמון, ומשם וואטסאפ |
| "דקות החודש X מתוך 150" בכל מספר | CRM, `loadLineStats` |
| **שיחה יוצאת - דקה וחצי לכל דקה** (`phone_line_outbound_minute_weight` = 1.5) | `charge_call_minutes()` לפי `direction = 'outbound'`, ‏`20270311090000` |

**שיחה יוצאת נספרת 1.5 (החלטה מ-7.10.2026).** היא עולה שתי רגליים - לנייד של הסוכן/ת ומשם ללקוח/ה:
כ-51 אגורות לדקה לנייד וכ-38 לקווי, מול כ-31 לנכנסת. בתקרה של 150 דקות יוצאות זה היה כ-₪97 עלות מול
₪89 שנגבים. השקלול על השניות ואז `ceil`, כמו בנכנסת: דקה יוצאת = 2, עשר דקות = 15. ‏`billed_minutes`
הוא דקות **משוקללות**, ולכן המכסה, ההתראות והחיוב מעבר לה (בפועל 0.75 ₪ לדקה יוצאת) עובדים בלי שינוי.
**השיחות היוצאות עצמן עוד לא בנויות** (למטה, "מה עוד לא כאן"): הכלל במסד מחכה להן, ומי שבונה אותן
רושם/ת `direction = 'outbound'` ומוסיף/ה את השקלול לטבלת ההשוואה ב-`pricing.html` ולשאלה הנפוצה.

**למה לא חוסמים שיחות כשאין יתרה:** לקוח/ה שלא נענה/תה עולה לסוכן/ת יותר מכל דקה. מה שנעצר
הוא מה שעולה לנו מעבר לניתוב ומה שהוא הערך של השירות - ההקלטה והסיכום. הדקות שכבר עברו בלי
כיסוי נבלעות אצלנו (`overage_charged = 0`). **ולכן ה-caller ID:** מתקשר/ת מחו"ל או חסוי/ה עובר/ת לנייד עם
המספר שלנו ולא עם שלו/ה (`onIncoming`), אחרת אותה דקה עולה פי שלושה. המספר הכלול ב-Elite עולה לנו את
אותו הדבר ואינו מכניס - הוא ממומן מדמי המנוי.

## חיפוש ומיון שיחות

מעל "שיחות אחרונות": חיפוש לפי שם לקוח/ה, טלפון או מילה מהסיכום, טווח תאריכים, ומיון (חדשות,
ישנות, ארוכות). **בשרת** (`refreshCallList`) ולא ברשימה שבזיכרון - היא מחזיקה רק את 60 האחרונות,
ושיחה מלפני חודשיים היא בדיוק מה שמחפשים. שם לקוח/ה מתורגם למזהים מקובץ הלקוחות (`client_id.in`),
ושם שנאמר בשיחה נחפש ב-`extracted->>caller_name`. בתצוגת המשרד אותם שדות, מקומית על 30 הימים
שכבר נטענו; שם מהקובץ של סוכן/ת אחר/ת אינו בידי המנהל/ת, ולכן שם שם המתקשר/ת מהשיחה.

## תצוגת המשרד: מנהל/ת רואה ומאזין/ה

קטגוריה **"שיחות המשרד"** ב-`#managerSection` (מנהל/ת משרד בלבד, `accOfficeCalls`):

- לכל סוכן/ת - 30 הימים האחרונים: שיחות, נענו, לא נענו, דקות החודש, והמספרים שלו/ה עם שיחות
  ושיחות שלא נענו לכל מספר.
- רשימת השיחות של המשרד (עד 100 מוצגות), סינון לפי סוכן/ת ו"רק שיחות שלא נענו", עם **השמעה
  ותמלול**. בלי ארכוב, מחיקה או הוספה לקובץ - אלה פעולות של הסוכן/ת על הקובץ שלו/ה.
- נטען רק כשהקטגוריה נפתחת.

ההרשאה במסד (`20270222090000_office_calls.sql`), קריאה בלבד, באותה צורה של
`agency_invitations_manager_read`: `current_member_role() = 'manager'` והסוכן/ת חבר/ה **היום** ב-
`current_agency_id()` - על `agent_calls`, `agent_phone_lines`, ותיקיית הסוכן/ת בדלי `call-recordings`.
סוכן/ת שעבר/ה משרד יוצא/ת מהתצוגה מעצמו/ה.

**שקיפות:** סוכן/ת במשרד שיש לו/ה מספר רואה מעל השיחות "מנהל/ת המשרד יכול/ה לראות את השיחות
במספרים שלך ולהאזין להקלטות" (`callsManagerNote`). הלקוח/ה שומע/ת בתחילת כל שיחה מוקלטת שהיא מוקלטת.

**המלכודת שנסגרה באותו PR:** השאילתות של הסוכן/ת עצמו/ה (`loadCalls`, `loadLineStats`,
`loadClientCalls`) נשענו על ה-RLS לבדו. ברגע שמנהל/ת יכול/ה לקרוא את שיחות המשרד, "שיחות אחרונות"
שלו/ה היו מתמלאות בשיחות של כל הסוכנים. לכן כל אחת מהן מסננת עכשיו `agent_id = currentAgent.id`
במפורש - **וכל שאילתה חדשה על הטבלאות האלה חייבת לעשות כך.**

## במשרד: שיוך, סבב, והתראה על שיחה שלא חזרו אליה

שלושתם בתצוגת "שיחות המשרד", למנהל/ת בלבד (`20270224090000_office_phone_routing.sql`):

**שיוך** - `office_phone_line_assign`: המספר עובר לסוכן/ת אחר/ת במשרד **עם החיוב** - החידוש הבא
יורד מהארנק של הבעלים החדש/ה, וחלון האישור אומר את זה. השיחות הישנות נשארות אצל מי שקיבל/ה אותן.
מספר כלול ב-Elite מאבד את ה"כלול" (הוא היה כלול במסלול של הקודם/ת), `forward_to` מתאפס, ואותו כלל
מסלול של `order_phone_line` חל: מחוץ ל-Elite, מי שכבר מחזיק/ה מספר בתשלום אינו/ה מקבל/ת שני.
שני הצדדים מקבלים הודעה בפעמון.

**סבב** - `ring_mode = 'round_robin'`, `ring_agents` (2 עד 8, לפי הסדר שנבחר), `rr_cursor`:

| שלב | |
| --- | --- |
| שיחה נכנסת | `phone_line_ring_next` מחזירה את הבא/ה בתור ומקדמת את התור (`onIncoming`) |
| אין מענה תוך 18 שניות | `onDial` מבקש/ת את הבא/ה אחרי מי שכבר צלצל (`ring_attempts`), עד ארבעה |
| מישהו ענה | הוא/היא `agent_id` של השיחה: הסיכום, ההקלטה והכרטיס אליו/ה |
| אף אחד לא ענה | השיחה נרשמת אצל מי שהתור היה שלו/ה (`ring_attempts[1]`), עם הלקוח/ה מהקובץ שלו/ה |

לכל סוכן/ת קובץ לקוחות משלו/ה, ולכן `client_id` וכרטיס ה"מתקשר/ת עכשיו" מחושבים מחדש בכל ניסיון
(`ringingClient`). סוכן/ת בלי טלפון או לא פעיל/ה מדולג/ת. התקרה, ההקלטה והחיוב - של המספר, כרגיל.

**התראה** - `agencies.missed_call_sla_minutes` (‏null = כבוי; 15 דקות עד 4 שעות מהמסך). cron כל 5
דקות (`claim_missed_call_sla_alerts`, בלי Edge Function): שיחה שלא נענתה, ממספר גלוי, שלא סומנה
**"חזרתי"** (`handled_at`, `agent_call_set_handled`) ושלא הגיעה אחריה שיחה שנענתה מאותו מספר -
שורה בפעמון לכל מנהל/ת, ומשם לוואטסאפ. בין 08:00 ל-21:00 בלבד, ועד 24 שעות אחורה.
**שיחה יוצאת מהנייד אינה נראית לנו**, ולכן "חזרתי" הוא סימון של הסוכן/ת - כפתור בשורת השיחה -
ולא זיהוי. בתצוגת המשרד: "חזרו אליו/ה" או "לא סומן שחזרו" לכל שיחה שלא נענתה.

## תא קולי

שיחה שלא נענתה (ובסבב - אחרי שאף אחד לא ענה) אינה נגמרת עוד ב"נחזור אליכם"
וניתוק: הלקוח/ה שומע/ת "השאירו הודעה אחרי הצליל", ו-`<Record>` מקליט עד שתי
דקות (חמש שניות שקט מסיימות). ההקלטה מגיעה ל-`?event=voicemail` ועוברת את
**אותו צינור** של שיחה מוקלטת - דלי, מחיקה מ-Twilio, Whisper, סיכום, וואטסאפ -
בכותרת "🎙️ הודעה קולית", עם אותם כפתורים (הוספה לקובץ, עדכון כרטיס, משימות).

| | |
| --- | --- |
| מתי אין תא קולי | אותו תנאי של הקלטה (`phone_line_recording_allowed`): מעבר ל-150 הדקות ובלי יתרה - "נחזור אליכם" כמו קודם |
| הודעה קצרה מ-2 שניות | ניתוק אחרי הצליל - נמחקת מ-Twilio בלי תמלול. ההתראה על השיחה שלא נענתה כבר יצאה |
| ב-CRM | אין עמודה חדשה: שיחה שלא נענתה ויש לה `recording_path` היא הודעה קולית, ומקבלת תגית "🎙 הודעה קולית" והשמעה |
| בדקות | **אינה נספרת** - `charge_call_minutes` סופר שיחות שנענו. עלותה לנו כ-12 אגורות להודעה של דקה (קבלה, הקלטה, Whisper וסיכום) |

ההתראה "שיחה שלא נענתה" יוצאת מיד, כמו קודם, וההודעה הקולית מגיעה אחריה
כשהתמלול מוכן - הסוכן/ת יודע/ת מייד, ולא מחכה לתמלול כדי לדעת שהתקשרו.

## ההודעות לסוכן/ת

| מתי | מה |
| --- | --- |
| **לקוח/ה מהקובץ מתקשר/ת** | בזמן שהנייד מצלצל: שם, מה מחפש/ת, הסיכום של השיחה הקודמת, וקישור שפותח את הכרטיס (`?goto=accClients&client=<id>`). דפדפן אינו יכול להקפיץ חלון על מסך השיחה, ולכן ההתראה בוואטסאפ היא ה"קפיצה" |
| **סיכום שיחה** | הסיכום, ההקלטה, ואחריהם הודעה עם **כפתורים**: "הלקוח לא ברשימת הלקוחות שלך, תרצה להוסיף אותו עכשיו?" (‏`כן, תוסיף`), עדכון הכרטיס (‏`כן, תעדכן`), ומשימות מהשיחה |
| **שיחה שלא נענתה** | מי, וכפתור הוספה או `תזכורת לחזור` |

**משימות מהשיחה:** הסיכום מחזיר גם `tasks` - מה שהסוכן/ת הבטיח/ה או מה שהלקוח/ה ביקש/ה
(`meeting`, `send_material`, `call_back`, `other`). לכל סוג כפתור (‏`TASK_BUTTON`): "קבע פגישה"
(‏`agenda_add`, ומועד פנוי מ-`agenda_free_slots` אם לא נקבע), "שלח חומר ללקוח" (‏`client_matches`
ואז `create_showcase`), "תזכורת לחזור". הלחיצה מגיעה לגבריאלה ככותרת הכפתור.

**ההודעות האלה יוצאות מ-twilio-voice ולא מהבוט**, ולכן הן נכתבות גם להיסטוריה של השיחה
(‏`rememberForBot`, זוג user/assistant), אחרת "כן" אחריהן היה מגיע לגבריאלה בלי הקשר. ‏
`last_message_at` לא משתנה: הוא מודד את חלון 24 השעות לפי מה שהסוכן/ת כתב/ה. מחוץ לחלון
יוצאת התבנית, בלי שמע ובלי כפתורים, והכפתור שבה פותח את הכרטיס.

## בכרטיס הלקוח/ה, ומחיקה

**"📞 שיחות והקלטות"** בכרטיס - השיחות לפי `client_id`, ולפי תשע הספרות האחרונות של הטלפון
(שיחה שהגיעה לפני שהלקוח/ה נוסף/ה נשמרה בלי `client_id`), עם הקלטה, תמלול וסיכום.

**🗄 ארכוב** - מסתיר שיחה מ"שיחות אחרונות" בלי למחוק אותה (הכפתור "ארכיון" מציג אותן).
העמודה `archived_at`, והכתיבה דרך `agent_call_set_archived()` - פונקציה שמשנה עמודה אחת, רק
בשיחה של מי שקורא/ת לה (מיגרציה `20270215090000_agent_calls_archive.sql`). אין policy של update:
היא הייתה מתירה לשנות גם את הסיכום או את `client_id`. שיחה בארכיון נמחקת אחרי 90 יום כמו כל שיחה.

**🗑 בכל שיחה** - `twilio-voice?task=delete`: ההקלטה מהדלי (‏Storage API) והשורה. ב-JWT רק
שיחות של הסוכן/ת; בקריאה פנימית (‏service_role / סוד ה-cron) - לניקוי חד-פעמי.

## סימולציה - כל הצינור בלי Twilio

ב-CRM, בבלוק "שיחות אחרונות", למנהל/ת הפלטפורמה בלבד: **"🧪 סימולציית שיחה"**.
מעלים הקלטה (הודעה קולית מוואטסאפ, הקלטה מהטלפון - ogg, m4a, mp3, wav, webm),
ואפשר לתת מספר של "מתקשר/ת" - מספר של לקוח/ה מהקובץ בודק גם את הזיהוי.
‏`twilio-voice?task=simulate` מאמת JWT ו-`is_platform_admin`, רושם שורה עם
`twilio_call_sid` שמתחיל ב-`SIM-`, ומריץ את אותו `analyzeCall` של שיחה אמיתית:
אחסון, תמלול, סיכום, הודעה בוואטסאפ. כך תקלה אחרי חיבור המספר היא של הטלפוניה,
ולא של הסיכום.

**שמות מקומות:** ‏Whisper שמע "רובע יזרעאל" כ-"ברוב הישראל". לכן כל תמלול נשלח
עם `prompt` - מילות התחום (שכירות, חדרים, ממ״ד, בלעדיות...) ואחריהן הערים
והשכונות של הסוכן/ת, מהנכסים ומהלקוחות שלו/ה לפי שכיחות (`agentPlaces`). אותה
רשימה עוברת גם לסיכום, ו-Claude מתקן לפיה שם שבכל זאת השתבש, אבל לא מנחש
מקום שאינו דומה לאף אחד מהם.

**הקלטות מאנדרואיד:** רשמקולים רבים שומרים m4a במעטפת שמסומנת `3gp4`, ו-Whisper
דוחה אותה ("Invalid file format") בכל שם קובץ, אף שהשמע בפנים הוא AAC רגיל.
`transcribe` מחליף בעותק את המותג בקופסת ה-`ftyp` ל-`M4A ` ושולח אותו קודם.
הקלטה ב-AMR (‏`sniff=mp4(3gp4,amr)` בלוג) לא תתומלל גם כך - Whisper אינו מכיר
את הקודק; הקלטה קולית מוואטסאפ (ogg) עובדת תמיד. שיחות Twilio עצמן מגיעות
כ-mp3 ואינן נוגעות בזה.
