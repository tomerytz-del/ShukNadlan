# נכס בלי תמונות (v10, ‏PR 1010 סבב 4 חלק 3)

**רק עם הדגל** (‏`html.beta-hero`, ‏`?beta=1`). בלעדיו כל דף מצייר את ממלא־המקום
הישן שלו בדיוק כמו קודם ("תמונות של הנכס יעלו בקרוב" עם לוגו המשרד).

## רנדרר אחד: `assets/no-photo.js`

‏`window.NoPhoto = { on, hasPhoto, level, html, useClient, setAgents, STR }`.
הסגנונות ב-`assets/no-photo.css`, ו-`no-photo.js` טוען אותם רק עם הדגל (לא חוסם ציור
בלי הדגל).

| משטח | איפה | מה |
| --- | --- | --- |
| `swipe` | כרטיס ב-`/swipe` | אווטאר, שם הסוכן/ת והמשרד, שכבת זכוכית עם הכותרת, ההסבר והכפתור "בקשו תמונות מהמפרסם". החלק התחתון (מחיר, פרטים) של הכרטיס |
| `card` | אריח במדף (‏`prop-shelf.js`), בנכסים דומים בדף הנכס, ובגלריה של גיליון ההחלקה | אווטאר מימין, כותרת, הסבר וקישור זהב |
| `row` | שורת תוצאה בדף הבית, שורות "רשימה" ו"אהבתי" ב-`/swipe` | אווטאר או איור, ותג "אין תמונות". ב-`/swipe` לשורה גם כפתור "בקשו תמונות" |
| `hero` | התא הראשי בדף הנכס | הסבר, כפתור זהב ו"יצירת קשר עם המפרסם", כרטיס המפרסם, ופס פרטים |

**"יש תמונה"** = תמונה תקינה ב-`images`, **או** `video_poster_url` (ואז הפוסטר הוא התמונה).

## שלוש רמות

```
cover = agencies.cover_url || agent.cover_url        // המשרד קודם
A  cover ועוד (לוגו המשרד או תמונת הסוכן/ת)
B  לוגו או תמונה בלבד
C  כל השאר, וגם מודעה פרטית
```

תמונה שנכשלה בטעינה יורדת לבדה והרמה מחושבת מחדש (A בלי שער = B, ובלי
אווטאר ולוגו = C) - לעולם לא מסגרת ריקה. תמונת הסוכן/ת עם `photo_position`.

**הסוכנים:** מי שכבר טען את `agency_members_public` מעביר `ctx.agent` (‏`/swipe`,
דף הנכס). אחרים קוראים ל-`NoPhoto.useClient(sb)` (דף הבית), והשורות משלימות את
עצמן (‏`MutationObserver`, שאילתה אחת לכל קבוצת מזהים).

**`show_photo_in_ads` אינו ב-view הציבורי** ולכן אינו נבדק (היום true או null אצל
כולם). כדי לכבד אותו צריך שה-view יחזיר `photo_url = null` כשהוא false - מיגרציה נפרדת.

## "בקשו תמונות מהמפרסם" - לעולם לא שולח לבד

| מאיפה | מה קורה |
| --- | --- |
| כרטיס ב-`/swipe`, שורה ב"רשימה" | גיליון הפרטים עם הטופס פתוח וההודעה `היי, ראיתי את <כותרת> בשוק הנדל״ן ואשמח לקבל תמונות של הנכס`; מקור הליד `photo_request` |
| אריח ושורה מחוץ להחלקה | קישור ל-`/property?id=…#contact&ask=photos` (הלחיצה נעצרת ב-capture כדי שהאריח לא ינווט בלי ה-hash) |
| דף הנכס | הטופס הקיים (‏`#inquiryForm`) עם ההודעה המלאה, ו-`source: 'photo_request'` |

הגולש/ת ממלא/ת שם וטלפון ושולח/ת. אירועים: `photo_request {property_id, level, surface}` בלחיצה,
ו-`generate_lead {form_id: 'photo_request'}` אחרי שליחה מוצלחת.

**המקור `photo_request`:** ב-`KNOWN_SOURCES` (‏`_shared/lead-routing.ts`, נבדק ב-
`scripts/lead_source_test.ts`), בתווית "בקשת תמונות" ב-`LX_SOURCES` (‏`crm.js`) וב-
`lead_source_label()` (מיגרציה `20271028120000_photo_request_source_label.sql`). הערוץ
(‏`lead_source_channel`) נשאר `other`. הליד מנותב ל-`properties.agent_id` כמו כל פנייה על נכס.

## סדר ב-`/swipe`

- **"רק נכסים עם תמונות"** בסינון, דלוק כברירת מחדל (‏`localStorage.sk_swipe_photos_only`,
  ‏`'0'` = כבוי). כשהנכסים עם התמונות נגמרים ויש מתאימים בלי - **כרטיס גשר** אחד (‏`np_bridge`):
  "המשיכו לראות נכסים מתאימים בלי תמונות", בלי כפתורים, וקישור "הצגה ברשימה" (הרשימה רק עם
  הנכסים האלה). החלקה לכל כיוון אינה אהבתי ואינה דילוג - היא ממשיכה לנכסים בלי התמונות
  (מקודמים, ואז החדשים), ואחריהם כרטיס הסיום.
- **כבוי:** הנכסים בלי תמונות נשזרים רק בזנב החפיסה - 7 עם ואחד בלי, ‏`k = min(N, floor(W/7))`.
  לעולם לא שניים ברצף ולא יותר מאחד בכל 8 כרטיסים (‏`?seqdebug=1` מריץ את הבדיקה). מי שלא
  נכנס לזנב מופיע ברשימה ובמפה.

## תוצאות ורשימות

נכס עם תמונה לפני נכס בלי **רק כשובר שוויון**: בשורות התוצאות בדף הבית (‏`sortSearchRows`) מיד
אחרי המקודמים במיון ברירת המחדל, ובמיון לפי מחיר או "חדש" רק כשהמפתח שווה; במדף - במיון המחיר
(מיון ברירת המחדל כבר מעדיף מדיה, ‏`sortByMedia`). נכסים בלי תמונות לא מוסתרים ברשימות, בתוצאות
או במפה.
