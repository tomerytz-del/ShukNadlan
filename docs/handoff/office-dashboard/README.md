# חבילת העברה: דאשבורד בעל משרד + הדשבורד האישי לסוכנים - שוק הנדל״ן

## מה בחבילה

| קובץ | מה זה |
| --- | --- |
| `HANDOFF.md` | **המסמך הראשי לקלוד קוד** - איפה זה יושב ב-CRM, מאיפה כל מדד מגיע, מה חסר במסד ואיך משלימים, עיצוב, כללי הריפו, סדר עבודה והגדרת "גמור" |
| `prototype/office-dashboard-prototype.html` | דאשבורד המשרד, כולל המלצות לשיפור הפריון - פתחו בדפדפן (לחיצה כפולה) |
| `prototype/agent-dashboard-prototype.html` | הדשבורד האישי לסוכן/ת - מוטיבציה, משימות היום, השוואה למשרד, עצות והישגים |
| `prototype/demo-data/*.json` | נתוני ההדגמה. המבנה שלהם הוא החוזה של ה-JSON שהפונקציות במסד צריכות להחזיר (`agent-demo.json` לדשבורד האישי) |
| `sql/draft_office_dashboard.sql` | טיוטת מיגרציה: `properties.closed_at`, טבלת `agent_targets`, והפונקציה `office_dashboard()`. לאמת מול המסד לפני הפעלה |
| `PROMPT.txt` | ההודעה להדביק בקלוד קוד |

## איך מעבירים לקלוד קוד

1. פרסו את התיקייה בתוך הריפו של שוק הנדל״ן, לנתיב `docs/handoff/office-dashboard/`.
2. פתחו את קלוד קוד בתיקיית הריפו.
3. הדביקו את התוכן של `PROMPT.txt`.

קלוד קוד יתחיל באימות הסכימה, יבנה את המיגרציה ואת הפאנל, ויעצור לשאול את ארבע השאלות הפתוחות שבסוף `HANDOFF.md` כשיגיע אליהן.

## שלוש נקודות שכדאי לדעת מראש

- **זמן תגובה ללידים לא נשמר היום במסד.** השלב הראשון משתמש בקירוב (מתי הליד נפתח או טופל), והשלב השני מוסיף עמודה אמיתית `first_response_at`.
- **אין היום שדה עמלה בפועל ואין יעדים.** העמלה מחושבת כהערכה (2% במכירה, חודש שכירות בהשכרה, או מה שכתוב בהסכם החתום). היעדים מקבלים טבלה חדשה, ועריכה ישירות מהדאשבורד.
- **הדאשבורד לקריאה בלבד.** זה תואם את ההחלטה שאין למנהל/ת סמכות ניתוב לידים.
