  "המיני-סייט שלי" ו"קידום ושיווק" הם יעדים קיימים במקום אחר (דף הסוכן/ת הציבורי, פעולות הקידום בכרטיס הנכס).
  אם אין להם קטגוריה, לקשר ליעד הקיים ולא ליצור קטגוריה ריקה. לבדוק מול `check_crm_nav.py`.
  `accBranding` עובר מתפריט הפרופיל לקבוצת הניהול.

- **קבוצה נפתחת ונסגרת** בלחיצה על הכותרת (`<button aria-expanded>`). הקבוצה של הקטגוריה הפעילה תמיד פתוחה.
  המצב נשמר ב-`localStorage` (‏`crmNavOpen`, אובייקט `{key: bool}`), עטוף ב-try/catch. ברירת מחדל: "עבודה יומית" פתוחה.
- **קבוצה סגורה מציגה מונה אדום מסוכם** של הפריטים הדחופים בה (`NAV_HOT_ACCS`). כך שום דבר דחוף לא מתחבא.
- **שורות של 36px** (היום יותר), אייקון 18px, רווח 1px. כותרת קבוצה 12px מודגשת באפור.
- **כיווץ לפס אייקונים (72px):** כפתור "כווץ תפריט" בתחתית. במצב הזה מוצגים רק אייקונים עם `title`/`aria-label`,
  והמונים יושבים על האייקון. המצב נשמר ב-`localStorage` (‏`crmNavRail`). מתחת ל-1100px אפשר לכווץ אוטומטית (החלטה ב-PR).
  התוכן משתמש ב-`flex: 999 1 560px`, כך שהוא מתרחב לבד.
- **מתג תצוגה למנהלים** בראש הסרגל: "אני כסוכן/ת" / "הצוות שלי" או "המשרד שלי". מוצג רק כש-`is_active_agent` (סעיף 3).
  כשהמנהל/ת בתצוגת הניהול, קבוצת הניהול ראשונה. בתצוגה האישית היא אחרונה.
  אצל מנהל/ת שאינו/ה סוכן/ת פעיל/ה: אין מתג, ומוצגת רק קבוצת הניהול (וקבוצת האדמין אם רלוונטי).
- **בתחתית:** מכסת הלידים החינמיים והיתרה בארנק (קיים היום ב-footer של הסרגל), ו"עזרה וסיור מודרך".
- **"יצירה חדשה"** בראש הסרגל פותח את אותו גיליון יצירה של הנייד (2.3), עם קיצור מקשים `N`.

### 2.2 הסרגל התחתון בנייד

**היום:** `NAV_TABS` = ראשי, נכסים, לידים, לקוחות, הסכמים, עוד. כל קטגוריה משויכת ללשונית דרך `tab`

**סיכון עיקרי:** הלשוניות "נכסים", "לקוחות", "הסכמים" ו"עוד" נעלמות. הגישה לקטגוריות שלהן בנייד:

ההתראות עוברות מהסרגל לפעמון בכותרת (קיים).

### 2.4 חיפוש אחוד

`design/Mobile-Search.dc.html`; במחשב, שדה בראש העמוד עם `Ctrl K`.
אין היום חיפוש אחוד (יש חיפוש בתוך קטגוריות, למשל `agrSearch`). חדש:

- **RPC‏ `crm_search(p_q text, p_limit int default 6)` returns jsonb**, `security definer`, רק על `current_agent_id()`.
  הקבוצות: נכסים שלי, לקוחות (שלי + שהופנו אליי, לפי ה-RLS הקיים של `agent_clients`), לידים, הסכמים.
- **לידים בחיפוש** עוברים את אותו מיסוך של `leads_masked`: ליד נעול מחזיר שם ממוסך ובלי טלפון. **לא** להחזיר `raw_phone`.
- חיפוש לפי טלפון: נרמול כמו ב-`lead_visitor_groups` (ספרות, 972→0) והתאמה ל-9 הספרות האחרונות. מחזירים את הפריט, **לא את הטלפון**.
- מינימום 2 תווים, debounce של 250ms. סינון לפי סוג בצ'יפים. **ספירה במסד**, לא בהורדת שורות (‏`crm-startup`).
- **עזרה:** קובץ סטטי `assets/crm-help.json` (שאלה, תשובה קצרה, קישור לקטגוריה), שמחופש בדפדפן. ולצדו "שאל את גבריאלה" (קישור הוואטסאפ הקיים).
- הרשאות: `revoke ... from public, anon, authenticated; grant execute ... to authenticated;`.

### 4.1 `team_dashboard(p_from date, p_to date) returns jsonb`

### 6.2 חוזה הפלט v2 (`summary jsonb`)

```jsonc
{
  "v": 2,
  "headline": "string",            // משפט פתיחה
  "summary": "string",             // 1-2 משפטים
  "strength": "string",            // צ'יפ ירוק
  "focus": "string",               // צ'יפ כתום
  "actions": [                     // 1-3
    { "priority": "high|mid|win", "title": "...", "why": "...", "impact": "...",
      "cta": { "kind": "<CTA_KINDS>", "ref": "<id אופציונלי>" } }
  ],
  "questions": ["...", "...", "..."],
  "agenda": ["..."]                // team בלבד, אופציונלי: סדר יום לישיבת צוות
}
```

`cleanSummary()` מתרחבת ל-v2: מקף ארוך, אורכים, עד 3 פעולות, `cta.kind` מהרשימה הסגורה בלבד
(אחרת הפעולה נשארת בלי כפתור). **הכרטיס יודע לקרוא גם v1** (כותרת + 3 נקודות) של `office_coach_summaries` הישנים.

### 6.3 `CTA_KINDS`: רשימה סגורה, ורק יכולות קיימות

| kind | פותח | זמין ל- |
| --- | --- | --- |
| `open_lead` | `openLeadFromParam(ref)` | agent |
| `open_leads_unanswered` | `accLeads` מסונן ללא מענה | agent |
| `open_property` | `openPropertyFromParam(ref)` | agent |
| `open_agreement` | `openAgreementFromParam(ref)` | agent |
| `new_agreement` | "החתם לקוח" | agent |
| `open_agenda` | `agendaFocus` | כולם |
| `new_agenda_item` | יצירת פגישה או משימה ביומן **של הקורא/ת** | כולם |
| `promote_property` | פעולת הקידום על נכס | agent |
| `open_prefs` / `open_profile` / `open_matches` | `accPrefs` / `accProfile` / `accAlerts` | agent |
| `open_team_agent` | שורת הסוכן/ת בדאשבורד הצוות או המשרד | team, office |
| `open_expiring` | "בלעדיות שפוקעות" | office |
| `open_promote_office` | קידום המיני-סייט של המשרד, **אם קיים** | office |

**בעיצוב יש כפתורים בלי יכולת מאחוריהם:** "צור זוג חונכות", "שלח מילה טובה", "שבץ למנהלי הצוות".
**לא לבנות להם כפתור.** במימוש הם נעשים `new_agenda_item`: משימה ביומן של המנהל/ת, למשל "שיחת חונכות: מיכל ונועה".
הכלל של `docs/office-coach.md` חל על שלושת המאמנים: **כל יכולת שהמאמן מזכיר חייבת להופיע ברשימת הכלים בפרומפט,
והפרומפט אוסר להמליץ על יכולת שאינה שם.** במיוחד: אין העברת ליד בין סוכנים, וגבריאלה לא פונה ללידים.

### 6.4 מאמן הסוכן/ת: יומי

- **טבלה** `agent_coach_summaries (id, agency_id, agent_id, day date, summary jsonb, model, input_tokens, output_tokens, actions_done smallint[] default '{}', created_at)`,
  `unique (agent_id, day)`. ‏RLS: select רק `agent_id = current_agent_id()`. אין כתיבה ל-`authenticated` (שלב "בוצע" דרך RPC, 6.7).
- **הפונקציה:** הרחבה של `office-coach` עם `?kind=agent|team|office` (ברירת מחדל office), שמשתמשת באותם `payload.ts`, `cleanSummary` ומטמון פרומפט.
  אם הקובץ מתנפח, אפשר `coach` חדשה שמייבאת מ-`_shared/`. **אותו אימות** (`_shared/cron-auth.ts`).
- **pg_cron:** `agent-coach`, כל יום ב-`10 3-5 * * *` UTC (בערך 06:10-08:10 בשעון קיץ), דרך `agent_coach_due(p_limit)`:
  סוכנים פעילים (`active`, `is_active_agent`), עם תנועה ב-14 הימים האחרונים, ובלי סיכום היום. **מנות** בגלל 150 השניות.
- **מה נשלח למודל** (רשימת `keep` סגורה): המדדים האישיים מ-`_agent_period_stats` (7 ו-30 יום), `office_avg` **רק כשקיים**
  (שלושה סוכנים ומעלה), ספירות ה-todo, סיכום הנקודות של אתמול, ומין דקדוקי. **לא נשלחים:** שמות עמיתים, שמות או טלפונים
  של פונים ולקוחות, וכתובות.
  כדי שה-CTA יוכל לפתוח פריט, שולחים **מזהי פריטים אטומים**. המודל מחזיר `ref` מתוכם בלבד, ו-`cleanSummary` מוחק `ref` שלא נשלח.
- **עלות:** קריאה לכל סוכן/ת פעיל/ה לכל יום. המודל בסוד `AGENT_COACH_MODEL`, וכדאי מודל קטן מזה של המשרד.
  **לדלג** על יום שבו לא השתנה דבר מאתמול (טביעת אצבע של הקלט) ולהעתיק את הסיכום. לרשום טוקנים בטבלה.
- **פרטיות** (כמו `my-dashboard.md`): הסיכום של סוכן/ת מוצג רק לו/ה. מנהלים לא רואים אותו.

### 6.5 מאמן מנהל/ת הצוות: שבועי

- **טבלה** `team_coach_summaries (id, agency_id, team_id, week_start, summary jsonb, model, tokens..., actions_done, created_at)`,
  `unique (team_id, week_start)`. ‏RLS: select למנהל/ת הצוות (`team_id = current_led_team_id()`) ולמנהלי המשרד של אותו משרד.
- **cron:** יחד עם `office-coach` ביום ראשון, `kind=team`. הקלט: `_office_dashboard_core` עם סוכני הצוות (4.1), לשבוע ול-30 יום,
  והנקודות של השבוע הקודם. **שמות סוכני הצוות מותרים** (מנהל/ת הצוות רואה אותם ממילא). שמות לקוחות אסורים.

### 6.6 מאמן המשרד

ממשיך מ-`office_coach_summaries`. משנים: הכותרת בכרטיס, חוזה הפלט ל-v2 (6.2), והוספת `actions_done`.
מוסיפים לקלט גם את `teams` (סעיף 5), כדי שיוכל לדבר על צוותים.

### 6.7 "סמן כבוצע"

`coach_action_done(p_kind text, p_summary_id uuid, p_index int, p_done bool)`, ‏`security definer`. בודקת שהקורא/ת רשאי/ת לקרוא
את השורה (אותם תנאים של ה-RLS) ומעדכנת את `actions_done`. הרשאות: authenticated בלבד.

### 6.8 בנייד

`design/Mobile-Coach.dc.html`: מסך מלא שנפתח מכפתור "המאמן" בכותרת דף הבית. למנהלים יש מתג "אני כסוכן/ת / הצוות או המשרד שלי".
בגרסה המקוצרת (`compact`) מוצגים שני צעדים.

## 7. שלב 6 - מדריך ההתחלה החדש

`design/Onboarding-Desktop.dc.html`, `design/Onboarding-Mobile.dc.html`. טיוטה: `sql/draft_04_onboarding_state_v2.sql`.

### 7.1 היום

`agent_onboarding_state()` (‏`docs/agent-onboarding.md`) מחזירה
`is_manager, whatsapp_done, profile_done, agency_done, property_done, client_done, agreement_done, lead_done, just_finished, about_done`.
הכרטיס `#onbGuide` עם `ONBOARD_STEPS` (`crm.js` ~7573) מציג 3 צעדים: גבריאלה, נכס ראשון, תמונה. למנהל/ת גם "על המשרד".
**אימות הרישיון אינו במדריך.** הוא כרטיס נפרד בראש הדשבורד, למרות שבלעדיו **דף הסוכן/ת, דף המשרד והמודעות אינם מוצגים באתר**
(`license_hold_at`, `docs/broker-registry.md`).

### 7.2 היעד: 7 צעדים בשני שלבים, לפי דחיפות

| # | שלב | צעד | נסגר כש... (לאמת) | הכפתור |
| --- | --- | --- | --- | --- |
| 1 | להופיע באתר | **אימות רישיון תיווך** | הרישיון מאושר: **אותו תנאי** שמשחרר את `license_hold_at` (`agency_members_release_license_hold`) | "העלאת אישור רישיון" (הזרימה הקיימת של כרטיס הרישיון) |

| 3 | להופיע באתר | **הנכס הראשון** | `property_done` (קיים) | "העלאת נכס"; משני: "לשלוח לגבריאלה" |
| 4 | להתחיל לעבוד | **חיבור גבריאלה בוואטסאפ, העוזרת האישית** | `whatsapp_done` (קיים) | "חיבור בלחיצה" (`assistantWaUrl`, קיים) |
| 5 | להתחיל לעבוד | **הלקוח/ה הראשון/ה** | `client_done` (קיים, היום לא סוגר את המדריך) | "הוספת לקוח/ה"; משני: "ייבוא אנשי קשר" |

| + | מנהל/ת בלבד | לוגו ו"על המשרד" | `agency_done` + `about_done` (קיים) | למיתוג |

**הניסוח:**
- **צעד 4:** גבריאלה היא העוזרת האישית: מעלה נכסים ולקוחות מהוואטסאפ, קובעת פגישות ועונה על שאלות (החלטה 6).
- **צעד 7:** כאן מסבירים את 12 שעות הבלעדיות של ליד בעלים.
- **מסלול:** הצעד של גבריאלה מגודר היום ל-`mid`/`premium`. למסלול חינמי מוצג "זמין במסלול..." ולא צעד פתוח
  (ההיגיון הקיים: "מדריך שמתחיל בהוראה לעשות משהו שהמסלול אינו כולל הוא פרסומת"). **לאמת מול `pricing-and-tiers.md`.**

**יומן Google:** ב-`docs/agent-onboarding.md` כתוב "יומן Google אינו צעד", כי בקשת הרשאה לפני שיש פגישה מבריחה.
**תומר החליט להחזיר אותו (החלטה 5).** לעדכן את הסעיף שם ולשמור את ההצעה הקיימת בפגישה הראשונה למי שדילג/ה.

### 7.3 הממשק

1. **Hero:** טבעת התקדמות X/7, כותרת לפי המצב ("בוא/י נעלה אותך לאוויר" / "את/ה באתר..." / "מוכנים!"),
   ו**צ'יפ מצב אמיתי**: "הדף שלך עוד לא מוצג לגולשים" כשהרישיון לא מאושר, "הדף שלך מוצג לגולשים" כשכן.
   משך משוער כולל, ו"אחר כך" שמקפל לשורה אחת עד סוף הביקור (כמו כרטיס הרישיון היום).
2. **"הצעד הבא":** כרטיס גדול עם השלב, המשך המשוער, למה זה חשוב (משפט אחד), כפתור ראשי ומשני.
3. **"כך רואים אותך באתר":** תצוגה מוקטנת של דף הסוכן/ת מהנתונים האמיתיים. כל חלק חסר מסומן במסגרת מקווקוות
   (תמונה, משפט, נכס). רק מה שכבר נטען בדשבורד, בלי שאילתה נוספת.
4. **כל הצעדים:** שלושה שלבים, תגית לכל שלב ("דחוף" / "השבוע" / "רשות" / "הושלם"), שורה לצעד הבא מודגשת.
   **הצעדים אינם נעולים** (כמו היום).
5. **נייד:** פס התקדמות של 7 מקטעים, כרטיס "הצעד הבא" ורשימה קומפקטית (40px לשורה), מעל דף הבית.

### 7.4 במסד

- `agent_onboarding_state()` מחזירה `table(...)`. **הוספת עמודות דורשת `drop function` + `create`**, ואז להחזיר את ההרשאות.
  להוסיף **בסוף**: `license_done, bio_done, calendar_done, prefs_done, cover_done, review_done, invite_done`.
  `client_done` כבר קיים, ועכשיו הוא סוגר צעד.
- **נשאר אותו עיקרון:** המצב מחושב בכל קריאה, ואין צ'קליסט שמסמנים. נכס או לקוח/ה שנפתחו דרך גבריאלה סוגרים את הצעד בדיוק כמו מהטופס.
- **תנאי הפתיחה** (אין נכסים ואין לקוחות) נשאר. "המדריך נסגר" = כל 7 הצעדים, או הסתרה (`agent_onboarding_dismiss`).
- **דרבונים בפעמון:** `onboarding_property` קיים. אפשר להוסיף `onboarding_client` ו-`onboarding_calendar` בטריגר על הצעד הקודם,
  לפי סקיל `agent-notifications` (סוג חדש בארבעה מקומות, ולאילוץ רק דרך `notification_types_add`).
- **‏`is_active_agent = false`:** המדריך מציג רק את צעדי המשרד.
