# אנשי קשר ושיחות אל ה-CRM

המטרה: הלקוח/ה שהסוכן/ת דיבר/ה איתו/ה עכשיו נכנס/ת לקובץ הלקוחות בלי
להקליד שם וטלפון, ומי שכבר בקובץ לא נכנס/ת פעמיים.

## מה הטלפון מרשה, ומה לא

| | אתר / אפליקציה מותקנת (PWA) | אפליקציה מהחנות |
| --- | --- | --- |
| יומן שיחות - אנדרואיד | **אין API** | רק לאפליקציית חיוג (מדיניות Google Play) |
| יומן שיחות - אייפון | **אין API** | **אין API** |
| אנשי קשר - אנדרואיד (כרום) | חלון בחירה של המערכת (`navigator.contacts`) | כן |
| אנשי קשר - אייפון (ספארי) | אין | כן, בהרשאה |

לכן **אין כאן קריאה של יומן השיחות**, ולא תהיה ממכשיר הסוכן/ת. מה שיש הם
הפתחים שלמטה, ויומן שיחות אמיתי יגיע רק ממרכזייה בענן (Voicenter, בסוף
המסמך).

**אף פתח אינו מעלה את ספר הטלפונים כולו.** בכל אחד מהם הסוכן/ת בוחר/ת מי
נכנס, ורק הם נשמרים. ספר טלפונים שלם של סוכן/ת הוא מאגר מידע אישי על
אנשים שלא ביקשו להיות בו, וזה לא מקום שנכנסים אליו בשביל נוחות.

| --- | --- | --- | --- | --- |

| 2 | "📇 מאנשי הקשר" בטופס הלקוח ובאשף ההחתמה | `crm.js` | - | ✓ כרום |

### 1. שיתוף איש קשר לעוזר - הדרך הראשית

בשיחות האחרונות: איש הקשר ← שיתוף ← וואטסאפ ← העוזר. ‏Meta מעבירה את
הכרטיס כהודעה מסוג `contacts`, ו-`contactsToText` הופך אותו לטקסט שמתחיל
ב-`[איש קשר ששותף]`. ליד כל כרטיס כתוב אם הטלפון כבר בקובץ. **הבדיקה נעשית
בקוד ולא מבוקשת מהמודל**, לפי תשע הספרות האחרונות, בדיוק כמו בדיקת הכפילות
של `create_client`.

מה העוזר עושה (הפרומפט, `SYSTEM_STATIC` ב-`agent.ts`):

* יש הוראה לידו ("תוסיף כקונה בחיפה עד 2 מליון") - מבצע.
* אין הוראה - שאלה אחת: "להוסיף את X כלקוח/ה? מה מחפש/ת?", ואפשר לענות
  בהקלטה. "כן" לבד יוצר כרטיס עם שם וטלפון.
* כבר בקובץ - לא יוצר, אומר בשם שבקובץ ושואל מה לעדכן.
* כרטיס עם חברה (`org`) עשוי להיות בעל/ת מקצוע ולא לקוח/ה - שואל לפני.

עד השינוי הזה כרטיס כזה קיבל "אני יודע לקבל טקסט, תמונות והקלטות".

### 2. חלון הבחירה של המערכת

`navigator.contacts.select` - כרום באנדרואיד בלבד. הכפתור מוצג רק כשה-API
קיים, ולכן באייפון ובמחשב הוא פשוט אינו שם. הדף רואה רק את מי שנבחר.

* **בטופס לקוח/ה חדש/ה** - ממלא שם, טלפון ומייל, ומעביר את הפוקוס להמשך.
  אם הטלפון כבר בקובץ - מציע לפתוח את הכרטיס הקיים במקום.
* **באשף "החתם לקוח"** - "חותם/ת מאנשי הקשר": מי שבקובץ נכנס/ת כלקוח/ה
  מהקובץ (עם ת.ז. וכתובת שכבר שמורות), וכל השאר כחותם/ת ידני/ת.

### 3. שיתוף אל האפליקציה המותקנת

`share_target` ב-`app-crm.webmanifest` מכניס את אפליקציית ה-CRM לתפריט
"שתף" של אנדרואיד (רק אחרי התקנה). הכרטיס מגיע כ-`.vcf` ב-POST ל-
`/crm-share`; ‏`sw.js` תופס את הבקשה, שם את הכרטיס ב-Cache Storage ומפנה ל-
`/crm?share=contacts`. ‏`handleShareParam` ב-`crm.js` קורא ומוחק:
כרטיס אחד נפתח בטופס, כמה כרטיסים נפתחים ברשימת הבחירה.

**למה זה לא סותר את "ה-Worker בלי מטמון"** (`docs/pwa-install.md`): שום
בקשה אינה מוגשת מה-Cache. הוא משמש תיבת דואר לכרטיס אחד, שנמחקת בקריאה
הראשונה.

**אייפון אינו תומך ב-`share_target`.** שם הדרך היא פתח 1.

### 4. הודעה מועברת

‏Meta מסמנת הודעה מועברת ב-`context.forwarded`. טקסט, הקלטה וכיתוב של
תמונה כאלה מקבלים את הקידומת `[הודעה מועברת - נכתבה במקור על ידי מישהו
אחר]`. **בלי הסימון המודל היה קורא "תוריד את המחיר" של לקוח/ה כהוראה של
הסוכן/ת.**

העוזר מחלץ דרישות (עיר, חדרים, תקציב), מסכם בשורה ומציע לפתוח או לעדכן
כרטיס. וואטסאפ **אינו** מעביר את שם השולח/ת המקורי/ת, ולכן: אם שותף איש
קשר באותו רצף - הדרישות שלו/ה; אחרת העוזר שואל של מי, ולא מנחש.

מודעה מועברת עם הוראה של הסוכן/ת לידה ("מחיר 1.9 תפרסם") ממשיכה להיות נכס
לפרסום, כמו קודם - ההוראה שלו/ה קובעת.

### 5. ייבוא מקובץ או מ-Google

כפתור "📇 ייבוא מאנשי הקשר" בראש קובץ הלקוחות. המקורות שמוצגים הם רק אלה
שעובדים בדפדפן הזה.

* **קובץ vCard** - מהאייפון (אנשי קשר ← בחירה ← שיתוף ← ייצוא vCard) או
  מאנדרואיד. הפענוח מטפל ב-`QUOTED-PRINTABLE`, שבו אנדרואיד ישן כותב כל שם
  בעברית, ובקיפול שורות.
* **קובץ CSV** - ייצוא "Google CSV" או "Outlook CSV" מ-contacts.google.com.
  כמה מספרים בתא אחד (` ::: `) מפוצלים.
* **Google Contacts** - ‏People API בהרשאת `contacts.readonly`, טוקן בזיכרון
  הדף בלבד. הטוקן מבוטל מיד בסוף הקריאה: אין refresh token ואין סנכרון
  ברקע. זה ייבוא בלחיצה, לא חיבור קבוע.

**שני כללים במסך הבחירה:**

1. **מי שכבר בקובץ מסומן/ת ואינו/ה ניתן/ת לבחירה.** אותה השוואה של תשע
   ספרות. בלי טלפון - לפי שם מדויק בלבד ("דני" אינו "דני כהן").
2. **כמה אנשי קשר נכנסים בסטטוס "בהמתנה" (`paused`).** לקוח/ה בלי דרישות
   מתאים/ה לכל נכס (שדה ריק = "לא משנה", `client-matching.md`), ומאה כאלה
   היו מציפים את ההתאמות וההתראות. מנוע ההתאמות סופר רק `active`. איש קשר
   **אחד** נפתח במקום זה בטופס, כדי להשלים מה הוא/היא מחפש/ת לפני השמירה.

מקובץ, מחלון הבחירה או משיתוף - עד 20 אנשי קשר מסומנים מראש. מ-Google -
אף אחד: שם זה ספר טלפונים שלם, ובוחרים אחד-אחד עם החיפוש.

#### הפעלת Google Contacts

הכפתור מוצג רק כש-`GOOGLE_CLIENT_ID` ב-`assets/contact-import.js` אינו
ריק. **מוגדר מ-30.9.2026:** הלקוח של הכניסה עם Google בפרויקט `shuknadlan`
(‏`562003868349-ja2c…`, זה שה-redirect שלו הוא ה-callback של Supabase),
עם `https://shuknadlan.co.il` ב-*Authorized JavaScript origins*. ‏Client
ID ציבורי מטבעו - הוא מופיע בכל כניסה עם Google. השלבים, למי שמקים מחדש:

1. **Google Cloud Console** ← APIs & Services ← Library ← להפעיל
   **People API**.
2. Credentials ← OAuth client מסוג **Web application**. הכי פשוט: אותו
   לקוח של חיבור יומן Google (`GOOGLE_CALENDAR_CLIENT_ID`,
   `google-calendar.md`) - אותו פרויקט ואותו מסך הסכמה, כך שהאימות של
   Google נעשה פעם אחת לשני ה-scopes. מוסיפים לו ב-*Authorized JavaScript
   origins* את `https://shuknadlan.co.il` (היומן משתמש ב-redirect בשרת,
   ואנשי הקשר בחלון קופץ בדפדפן - שני שדות שונים באותו לקוח).
3. OAuth consent screen ← Data access ← להוסיף את
   `https://www.googleapis.com/auth/contacts.readonly`.
4. להדביק את ה-Client ID (לא ה-Secret) ב-`GOOGLE_CLIENT_ID`. הוא ציבורי
   מטבעו.

**מלכודת:** `contacts.readonly` הוא scope **רגיש**. כל עוד האפליקציה לא
עברה אימות של Google, רק חשבונות שמופיעים ב-*Test users* יכולים לאשר, וכל
השאר מקבלים "האפליקציה לא אומתה". האימות דורש את `privacy.html` עם סעיף
שמתאר את השימוש באנשי הקשר, ולוקח כמה ימים עד שבועות. עד אז פתח הקובץ
(Google CSV) נותן את אותה תוצאה בלי שום הקמה.

**ו-`privacy.html`:** הסעיף `#contacts` ("אנשי קשר וקובץ הלקוחות") מתאר
את כל חמשת הפתחים, כולל ה-Limited Use של Google וזה שכרטיס ששותף לעוזר
נשלח לספק המודל. מי שמשנה את אחד הפתחים מעדכן אותו באותו PR - זה הקישור
שמוגש ל-Google בבקשת האימות.

## יומן שיחות: Voicenter - השלב הבא

זו הדרך היחידה ליומן שיחות אמיתי. המספר של המשרד (או מספר וירטואלי לכל
סוכן/ת) עובר דרך המרכזייה בענן, והיא מדווחת על כל שיחה. **שום דבר מזה עוד
לא בנוי.** התכנון:

1. **קליטה** - Edge Function חדשה, `voicenter-cdr` (‏`verify_jwt = false`,
   סקיל `new-edge-function`), שמקבלת את דיווח השיחה ש-Voicenter שולחת
   בסוף כל שיחה. האימות: סוד משותף בכתובת או בכותרת, לפי מה ש-Voicenter
   תומכת - לבדוק מול התיעוד שלהם בזמן ההקמה.
2. **טבלה** - `agent_calls` (מיגרציה, סקיל `new-migration`): סוכן/ת, מספר
   הצד השני, כיוון, סטטוס (נענתה / לא נענתה), משך, זמן, ו-`client_id`
   כשהמספר מזוהה בקובץ לפי אותן תשע ספרות. RLS לפי `agent_id`, כמו
   `agent_clients`.
3. **שיוך סוכן/ת** - לפי השלוחה או המספר הווירטואלי, בטבלת מיפוי.
4. **מה זה נותן:**
   * "מי התקשר/ה היום ועוד לא בקובץ" - ב-CRM ובעוזר ("מי התקשר אליי היום?"),
     עם הוספה בלחיצה. זו התשובה המלאה ל"הלקוח האחרון שדיברתי איתו".
   * שיחה שלא נענתה מלקוח/ה קיים/ת - התראה עם מה הוא/היא מחפש/ת ומה
     מתאים לו/ה עכשיו.
   * תיעוד אוטומטי בכרטיס הלקוח/ה, ותזכורת על מי שלא דיברו איתו/ה זמן רב.
5. **מה צריך מהמשרד** - חשבון Voicenter, גישה להגדרות ה-API/CDR, והחלטה
   אם מספר אחד למשרד או מספר לכל סוכן/ת (משפיע על השיוך בשלב 3).
6. **מסלול** - כנראה יכולת של מסלול בתשלום. אם כן, הגייט במסד, השורה
   ב-`pricing.html` והשורה בתיעוד (סקיל `new-tier-capability`).

## בדיקה ידנית אחרי שינוי

* וואטסאפ: לשתף לעוזר איש קשר שאינו בקובץ, ואיש קשר שכן. להעביר לו הודעה
  קולית של "לקוח" עם דרישות.
* אנדרואיד/כרום: "📇 מאנשי הקשר" בטופס ובאשף. ‏CRM מותקן ← אנשי קשר ←
  שיתוף ← אזור אישי.
* כל דפדפן: ייבוא קובץ vcf עם שלושה כרטיסים, שאחד מהם כבר בקובץ.
