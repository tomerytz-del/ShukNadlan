# תיוג סוכנים ומשרדים בפרסומי הנכסים

מערכת הפרסום (רילס, סטוריז ופוסטים של נכסים, `docs/facebook-auto-publish.md`)
מוסיפה לכל פרסום תגובה שמתייגת את הסוכן/ת ואת המשרד:

- **אינסטגרם** - `@שם_משתמש` של הסוכן/ת ושל המשרד בתגובה.
- **פייסבוק** - דף יכול לתייג דף אחר (הדף העסקי של המשרד), אבל לא פרופיל
  אישי. לסוכן/ת נכתבים השם וקישור לדף שלו/ה באתר.

**מתייגים רק מי שאישר/ה.** שם משתמש בלי אישור אינו מתויג.

## איפה זה נשמר

| | טבלה | עמודות |
| --- | --- | --- |
| סוכן/ת | `agency_members` | `instagram_handle`, `facebook_url`, `social_tag_consent`, `social_tag_consent_at` |
| משרד | `agency_social` | `instagram_handle`, `facebook_page_url`, `social_tag_consent`, `social_tag_consent_at`, `social_tag_consent_by` |

**למה המשרד בטבלה נפרדת ולא ב-`agencies`:** ‏`agencies` ציבורית (‏select
לכל גולש/ת על משרד באוויר), ועמודה חדשה בה הייתה נקראת מיד מהדפדפן של כל
אחד. ‏`agency_members` כבר פרטית (השורה עצמה ומנהל/ת המשרד), ודפי הסוכנים
קוראים מ-views עם רשימת עמודות סגורה. השדות אינם מוצגים באתר.

המיגרציה: `supabase/migrations/20270904090000_social_tagging.sql`.

## כללים שהמסד אוכף

- **נרמול** - `social_instagram_norm()` מוריד `@`, קישור `instagram.com/...`,
  רווחים ואותיות גדולות; `social_facebook_norm()` מיישר ל-
  `https://www.facebook.com/...`. אחרי הנרמול אילוץ: אינסטגרם
  `^[A-Za-z0-9._]{1,30}$`, פייסבוק רק `facebook.com`. אותו נרמול משוכפל
  ב-`socialReadFields` ב-`assets/crm.js` וב-`readSocialFields` ב-
  `agency-signup.html`, כדי שהשגיאה תוצג בעברית לפני השמירה.
- **החותמת נקבעת בטריגר** - `social_tag_consent_at` נדלק ברגע שהאישור עובר
  ל-`true` ומתאפס בביטול. הדפדפן אינו כותב תאריך.
- **סוכן/ת בלבד על השורה שלו/ה** - ה-policy מתיר למנהל/ת לעדכן שורות של
  סוכני המשרד, ולכן `agency_members_social_fields()` מחזיר את ארבעת השדות
  לערכם הקודם כשמי שכותב/ת אינו/ה הסוכן/ת (או `service_role`). מנהל/ת אינו/ה
  יכול/ה לאשר תיוג בשם סוכן/ת.
- **המשרד - מנהל/ת בלבד** - RLS על `agency_social` לקריאה ולכתיבה.

## איפה ממלאים

- **הרשמת משרד** (`agency-signup.html`) - ארבעה שדות רשות ותיבת אישור אחת,
  לא מסומנת מראש, שחלה על המנהל/ת ועל המשרד. ‏`agency-signup` שומר אותם
  בעדכון נפרד: כשל משאיר משרד בלי אינסטגרם, ולא בלי משרד.
- **CRM, הפרופיל שלי** - הכרטיס "רשתות חברתיות". כל סוכן/ת, כולל מי
  שהצטרף/ה בהזמנה (הצטרפות בהזמנה היא בלי טופס, ולכן זה המקום).
- **CRM, דף המשרד** - "רשתות חברתיות" תחת המיתוג, למנהל/ת.

שני הכרטיסים נטענים בשאילתה נפרדת ונשמרים עם כפתור השמירה של הטופס. לפני
שהמיגרציה רצה הם מוסתרים, והשמירה מדלגת עליהם.

## מה מערכת הפרסום קוראת

‏`social_tag_targets` - view ל-`service_role` בלבד (לא `anon` ולא
`authenticated`). שורה לכל נכס פעיל:

| עמודה | |
| --- | --- |
| `property_id` | |
| `agent_id`, `agent_name`, `agent_page_url` | תמיד - שם וקישור לדף באתר הם ציבוריים ממילא |
| `agent_instagram`, `agent_facebook_url` | **null בלי אישור** |
| `agency_id`, `agency_name`, `agency_page_url` | תמיד |
| `agency_instagram`, `agency_facebook_page_url` | **null בלי אישור** |

השדות מסוננים לפי האישור כבר ב-view, כדי שהקורא לא יוכל לתייג בטעות מי
שלא אישר/ה. הקריאה בלבד: מערכת הפרסום אינה כותבת לטבלאות האלה.

```sql
select * from social_tag_targets where property_id = '<id>';
```
