# מדף הלידים של עורכי הדין

"שאלה לעו״ד" מדף נכס, כמדף לידים: גולש/ת משאיר/ה שאלה וטלפון, הליד מוצג לעורכי הדין **בעיר
של הנכס** בלי פרטי קשר, ומי שרוכש/ת (₪50 מהארנק) רואה אותם. אותו מוצר כמו לידי המשכנתאות
(`docs/mortgage-leads.md`), על קהל אחר.

> **מצב נוכחי:** התשתית בלבד (מיגרציה `20271107220000_lawyer_leads.sql`, ‏`lawyer-lead-purchase`,
> המגירה ב-CRM). **אין עדיין נקודת קליטה**: הטופס בדף הנכס, אימות הטלפון בוואטסאפ וההתראה
> לסוכן/ת באים ב-PR נפרד, והטבלה ריקה עד אז.

## העיקרון: ממוקד למי שביקש

ליד של עורך/ת דין לא מוצג למתווכים ולא ליועצי משכנתאות, ולהפך (`docs/lead-routing.md`, "מדפי
הלידים ממוקדים"). ההפרדה **ב-view עצמו**, לא ב-JS:

- `lawyer_leads_public` מחזיר שורות רק כש-`current_is_lawyer()` (עו"ד פעיל/ה, או מנהל/ת פלטפורמה).
- וגם רק לליד **בעיר שהעו"ד עובד/ת בה** (`current_agent_works_city`, שעוטפת את `agent_works_city`),
  או ליד בלי עיר, או מנהל/ת פלטפורמה.
- רק `status = 'new'`. ליד שנמכר יורד מהמדף, ומי שרכש/ה קורא/ת אותו מהטבלה (policy לפי `sold_to_agent_id`).
- **השאלה עוברת `redact_contact_text`**: שם משתמש ברשת, קישור, טלפון, מייל ושם הפונה מוסתרים,
  אחרת עו"ד היה פונה לפונה בלי לרכוש.
- `check_shelf_audience.py` (ו-`lawyer_leads_public` ב-`PROFESSIONAL_SHELVES`) חוסם ב-CI מדף שהשומר שלו הוסר.

נבדק מקומית על Postgres 16 עם סכימה מדומה: עו"ד בעיר א' רואה את הלידים של עיר א' ושל "בלי עיר",
עו"ד בעיר ב' את של ב', מתווך ויועץ משכנתאות 0, מנהל/ת פלטפורמה את כולם, ו-`anon` נדחה;
רכישה: מי שאינו עו"ד, ליד שלא אומת, יתרה חסרה, רכישה חוזרת (בלי חיוב נוסף) ועו"ד אחר (נדחה).

## החלקים

| מה | איפה |
| --- | --- |
| דגל `is_lawyer` | `agency_members`, נעול למנהל/ת פלטפורמה ב-`protect_sensitive_agency_member_fields` (בדיקה: `scripts/lawyer_shelf_test.mjs`, workflow `lawyer_shelf.yml`) |
| הלידים | `lawyer_leads` (`status`: `pending` לפני אימות · `new` במדף · `sold` · `archived`), ליד פתוח אחד לכל טלפון |
| הרכישות | `lawyer_lead_purchases`, `unique(lead_id)` |
| המדף | `lawyer_leads_public` |
| הרכישה | `purchase_lawyer_lead(lead, agent)` (service_role בלבד) דרך `lawyer-lead-purchase` (JWT + MFA) |
| המחיר | `pricing_config.lawyer_lead_price` (50). הארנק לפני מע"מ: הרכישה מורידה את המחיר הנקוב |
| ה-CRM | מגירה "עורכי דין" בחנות הלידים, מוסתרת ל-`is_lawyer = false` |

## לסמן עו"ד

כמו יועץ/ת משכנתאות: העו"ד נרשם/ת ל-CRM כרגיל, והנהלת הפלטפורמה מסמנת (SQL, או בקשה ל-Claude):

```sql
update public.agency_members set is_lawyer = true where id = '<agency_members.id>';
```

הדגל נעול מהדפדפן: סוכן/ת לא יכול/ה להעניק אותו לעצמו/ה.

## מה עוד לא כאן (ה-PR הבא)

1. **טופס "שאלה לעו״ד" בדף הנכס** עם אימות טלפון בוואטסאפ (הודעה נכנסת, כמו בחתימת הסכם:
   `agreement-wa-verify.ts`): הליד נכנס כ-`pending` ועולה למדף (`new`) רק אחרי האימות.
2. **התראה לסוכן/ת של הנכס** שהלקוח/ה ביקש/ה ייעוץ משפטי, עם קישור לנכס (הסקיל `agent-notifications`).
3. **`data_retention_run`** יכסה את `lawyer_leads` (שם, טלפון, מייל ושאלה) **לפני** ששורה ראשונה נכנסת
   (`docs/data-retention.md`).
4. **רישום ניתוב** ב-`lead_routing_log` (`lead_kind` חדש), כדי שליד שאין לו עו"ד בעיר ייראה למנהל/ת.
5. **הדיסקליימרים בעברית** בטופס: השאלה אינה יוצרת יחסי עו"ד-לקוח, ואין לשלוח סיסמאות, פרטי תשלום או מסמכי זהות.
