# מפת האתר ופיד הכתבות

## הבעיה שזה פותר

האתר סטטי, אבל רוב הכתובות שלו אינן. כל נכס, כתבה, משרד תיווך וסוכן/ת חיים
כשורה ב-Supabase ומוצגים דרך כתובת עם פרמטר:

| מה | הכתובת |
| --- | --- |
| נכס | `property.html?id=<uuid>` |
| כתבה | `article.html?slug=<slug>` |
| משרד תיווך | `agency.html?slug=<slug>` |
| סוכן/ת | `agent.html?slug=<slug>` |
| בעל/ת מקצוע | `professional.html?slug=<slug>` |

גוגל לא מגלה כתובות כאלה בעצמו — אין קישור סטטי אליהן משום מקום — ולכן עד
היום נסרקו בפועל רק העמודים הקבועים. ‏61 נכסים וארבע כתבות היו קיימים באתר
ובלתי נראים לחלוטין בחיפוש.

## איך זה עובד

```
cron יומי / מיזוג ל-main / הרצה ידנית
        ↓
sitemap_rss.py  →  קורא את Supabase  →  sitemap.xml + rss.xml
        ↓
הקבצים השתנו?  →  commit ל-main  →  Netlify מפרסם
```

* **`sitemap_rss.py`** — הסקריפט. כותב את שני הקבצים רק כשהתוכן באמת שונה
  ממה שכבר בריפו, ומחזיר קוד יציאה מתאים.
* **`.github/workflows/sitemap_rss.yml`** — מריץ אותו כל יום ב-04:10 UTC,
  בכל מיזוג ל-`main` שנוגע בעמודי HTML או בסקריפט, וגם ידנית מלשונית
  Actions (עם אפשרות `dry_run`).
* **`robots.txt`** — מפנה את הסורקים ל-`sitemap.xml`, וחוסם את מסכי
  האפליקציה (‏CRM, ניהול כרטיסייה, בקשת חוות דעת) שאינם תוכן.

אין סודות חדשים: ה-workflow משתמש ב-`SUPABASE_URL` וב-
`SUPABASE_SERVICE_ROLE_KEY` שכבר מוגדרים בריפו. ‏`SITE_URL` הוא Repository
Variable אופציונלי לדריסת הדומיין.

## מה נכנס לכל קובץ

**`sitemap.xml`** — העמודים הקבועים (כולל `/en/` ו-`/ru/` ועמודי המדיניות),
כל נכס `status='active'`, כל כתבה `status='published'`, כל משרד תיווך, כל
סוכן/ת פעיל/ה וכל כרטיסיית בעל/ת מקצוע פעילה. עמודי אפליקציה אינם נכנסים.

**`rss.xml`** — ארבעים הכתבות המפורסמות האחרונות, החדשה בראש. זה מה
שקוראי פידים ו-Google News מצפים לו, והוא מקושר מ-`<head>` של דף הבית ושל
עמודי המגזין כדי שדפדפנים וקוראי פידים יגלו אותו לבד.

## שלוש החלטות שקבעו את המבנה

1. **כתיבה רק כשיש שינוי.** ‏commit יומי אוטומטי גם כשכלום לא זז מרעיש את
   היסטוריית הגיט ומייצר בנייה מיותרת ב-Netlify. הסקריפט משווה לתוכן הקיים
   לפני שהוא כותב.
2. **כישלון שליפה מבודד לטבלה שלו.** אם `properties` נופלת, המפה עדיין
   נבנית עם הכתבות והעמודים הקבועים. מפה חלקית עדיפה על היעדר מפה, ובוודאי
   על מפה שנכתבת ריקה ומוחקת את הקודמת.
3. **בריחת XML ולא CDATA.** כותרת כתבה עם `&` או `<` היא מקרה רגיל; תיאור
   עם `]]>` בתוכו היה שובר `CDATA` בשקט. הבריחה הרגילה עובדת בכל קורא.

## תחזוקה

* עמוד סטטי חדש → להוסיף שורה ל-`STATIC_PAGES` בראש הסקריפט.
* טבלה חדשה שמייצרת כתובות ציבוריות → להוסיף לולאה ב-`collect_urls`.
* בדיקה מקומית בלי לכתוב: `python sitemap_rss.py --dry-run`.
* אחרי הפריסה הראשונה כדאי להגיש את `https://shuknadlan.co.il/sitemap.xml`
  ב-Google Search Console פעם אחת; מכאן והלאה גוגל מושך אותו לבד.
