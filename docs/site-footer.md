# הפוטר המשותף

פוטר אחד לכל 20 העמודים הציבוריים. ה-markup משוכפל בכל קובץ HTML (אין
תבניות בצד השרת — ‏Netlify מגיש קבצים סטטיים), אבל **העיצוב וההתנהגות
יושבים בקובץ אחד כל אחד**:

| | קובץ |
| --- | --- |
| עיצוב | `assets/site-footer.css` |
| התנהגות | `assets/site-footer.js` |
| הבאנר שבראשו | `assets/buyer-banner.css` + `assets/buyer-banner.js` |

עד שהם הופרדו החוצה הפוטר היה משוכפל בתוך ה-`style` של כל דף, בשלוש
גרסאות שונות, ומי שערך אחת השאיר את השאר מאחור. שינוי בפוטר נעשה בשני
הקבצים האלה; ב-HTML נוגעים רק כשהמבנה עצמו משתנה — ואז **בכל 20 הקבצים
יחד**, בסקריפט ולא ביד.

## המבנה

```
footer.site
├─ .footer-lead          ← באנר מחפשי הנכס (‏#buyerBanner)
├─ .footer-top
│   ├─ .footer-brand     ← לוגו, משפט מתאר, שלושה כפתורי הצטרפות, פרטי קשר, רשתות
│   └─ nav.footer-grid   ← ארבע קבוצות ניווט (details.footer-col)
├─ details#footerSeo     ← ענן החיפושים הפופולריים
└─ .footer-bottom        ← זכויות + קישורי החובה המשפטיים
```

## מרווח אחד: ‎--fs-gap‎

כל מעבר בין שני חלקים בפוטר — הרצועה שבראש לגוש המותג, גוש המותג לענן
החיפושים, ענן החיפושים לשורת הזכויות, וגם הריפוד העליון של הפוטר עצמו —
נמדד ב-`--fs-gap` אחד שמוגדר על `footer.site`. קודם כל מעבר כזה נשא מספר
משלו (‏26px, ‏24px, ‏34px), ולכן הפוטר נקרא כערימת בלוקים ולא כיחידה אחת.

**מי שמשנה מרווח בפוטר משנה את המשתנה, פעם אחת.**

## מה מקופל בטלפון

שני בלוקים נפתחים לפי רוחב המסך, ושניהם באותה שיטה: `<details open>`
ב-HTML, ו-`site-footer.js` סוגר אותם מתחת לסף שלהם (`fold()`).

| בלוק | סף | למה |
| --- | --- | --- |
| `details.footer-col` × 4 | 560px | עשרים קישורי ניווט הם שני שלישים מגובה הפוטר בטלפון |
| `details#footerSeo` | 760px | חמישה־עשר צ׳יפים תופסים שם שמונה שורות |

הסְפים שונים כי הרוחב שכל בלוק צריך שונה: הרשת נפתחת לארבע עמודות
ב-560px, והצ׳יפים מפסיקים לגלוש ב-760px.

**‏`open` ב-HTML ולא `closed` היא החלטה ולא ברירת מחדל.** בלי JS, ובעיני
סורק, הכול פרוש; והקישורים נשארים ב-DOM גם כשהבלוק סגור, ולכן מנוע החיפוש
והחיפוש בדפדפן (‏Ctrl+F) מוצאים אותם בכל מצב. מעל הסף ה-`summary` חוזר
להיות כותרת: בלי חץ, בלי `cursor:pointer`.

## הרצועה שבראש הפוטר — באנר מחפשי הנכס

בראש הפוטר, בכל עמוד ציבורי, יושבת `.footer-lead`: באנר מחפשי הנכס
(`#buyerBanner` — "מחפשים נכס? תנו לו למצוא אתכם"). שורת הזמנה אחת, ומתחתיה
— רק למי שלוחץ/ת — אשף בן שלושה שלבים ששומר חיפוש דרך `saved-search-intake`
(ראו `docs/smart-search-agent.md`).

עד 11.9.2026 ישבה שם `.footer-news`, רצועת ההרשמה לרשימת התפוצה. שתיהן
ביקשו מאותו אדם את אותו דבר במילים אחרות — "נעדכן אתכם כשיעלה נכס" — וזו
שומרת את **החיפוש** ולא רק את האימייל, כלומר התראה על נכס שמתאים במקום
סיכום שבועי. ‏`.footer-news` ירדה מכל העמודים; מה שנשאר ממנה מתועד ב-
`docs/newsletter.md`.

### שלוש הטמעות, ולמה לא אחת

| עמודים | מאיפה הבאנר | למה |
| --- | --- | --- |
| 17 העמודים הציבוריים | `assets/buyer-banner.css` + `assets/buyer-banner.js` | אין להם אשף משלהם, ושלוש שורות ב-HTML מספיקות |
| `index.html` | אשף מקומי בדף | קשור למחשבון התשואה (‏`openBuyerSearch()`, מקור `homepage_yield_calc`) ולרשימת השכונות שהדף כבר טען |
| `agency.html`, `agent.html` | אשף מקומי בדף | ההסכמה, מסך הסיום ואזור ברירת המחדל נושאים את שם המשרד ואת עיר הפעילות שלו |

הקובץ המשותף עצמאי לחלוטין — כתובת הפרויקט, המפתח הציבורי, רשימות סוגי
הנכס וקריאת השכונות ב-REST — ואינו נשען על שום משתנה של הדף המארח. עמוד
שטוען אותו **לא** יכול לשאת אשף מקומי נוסף: שני `#buyerBanner` באותו מסמך
הם שני טפסים עם אותם מזהים.

`data-source` על הבאנר נרשם ביומן הניתוב. הערך של הקובץ המשותף הוא
`footer_buyer_wizard`, והוא חייב להופיע ב-`KNOWN_SOURCES`
(`supabase/functions/_shared/lead-routing.ts`) — מקור שאינו ברשימה נרשם
תחת ברירת המחדל, כלומר הליד מגיע אבל היומן משקר לגביו.

`.footer-lead` היא `.footer-wrap` שבתוכה כרטיס, ולא רצועה ברוחב מלא כמו
שהייתה `.footer-news`: הבאנר נפתח לאשף בן שלושה שלבים, וטופס מקצה לקצה
המסך אינו כרטיס אלא עמוד.

## נעילת הלוגו

`.footer-logo-word` היא אותה נעילה של הכותרת — שם, קו זהב, אזור — רק
בצבעים של רקע כהה. הפירוט ב-`docs/logo.md`.

## כללים שמחזיקים את הקובץ עצמאי

הפוטר מופיע גם בעמודים שאין בהם שום קוד אחר (הקוד האתי, השאלות הנפוצות),
ולכן:

1. **צבעים מפורשים ולא משתני CSS.** ‏`var(--teal-dark)` קיים ב-`index`
   אבל לא בכל דף, ופוטר בלי רקע הוא פוטר בלתי קריא.
2. **‏`.footer-wrap` ולא `.wrap`.** ל-`.wrap` יש רוחב מרבי אחר בכל דף
   (‏860px בקוד האתי, ‏1180px בדף הבית), והפוטר צריך להיראות זהה בכולם.
3. **‏`site-footer.js` עצמאי לחלוטין** — הוא מחזיק את כתובת הפרויקט ואת
   המפתח הציבורי בעצמו, ולכן אפשר להכליל אותו בכל עמוד בשורה אחת.

## 11.9.2026 — הקיצור

הפוטר בטלפון היה ארוך ממסך שלם, ובדף הבית הצטרף אליו פס לבן ריק בגובה
כמעט מסך בין באנר מחפשי הנכס לראשו. מה שהשתנה:

* הבאנר נכנס **לתוך** הפוטר (`.footer-lead`) במקום להיות הבלוק האחרון
  ב-`main`, ושלושת המרווחים שהצטברו בין השניים ירדו לאחד.
* רצועת ההרשמה לרשימת התפוצה ירדה מהפוטר, והבאנר תפס את מקומה **בכל
  העמודים** — ‏17 מהם דרך `assets/buyer-banner.*` החדשים.
* ארבע קבוצות הניווט נעשו `details` ומקופלות מתחת ל-560px.
* כל המרווחים אוחדו ל-`--fs-gap`, והריפודים הפנימיים הודקו.
* נעילת הלוגו של הכותרת החליפה את הניסוח הנפרד שהיה כאן.
* גוש המותג עולה לצד הקישורים כבר מ-900px ולא מ-1024px.
