# תיאום ביקור עם הבעלים והמתווכים

לקוח/ה ביקש/ה במיניסייט סיור בכמה נכסים ([`client-showcase.md`](client-showcase.md)).
חלק מהנכסים של הסוכן/ת, וחלק של מתווכים אחרים: עמית/ה במשרד, או משרד בשת"פ.
לפני היכולת הזו כל סיור כזה היה כמה שיחות טלפון, כל אחת עם אותה שאלה: "אפשר
לבוא היום בסביבות חמש?".

עכשיו גבריאלה שואלת את הסוכן/ת אם לשלוח לכולם, ובאישור יוצאת לכל אחד/ת הודעה
בוואטסאפ עם שלושה כפתורים. כל תשובה חוזרת לסוכן/ת כהתראה.

## הזרימה

1. **הלקוח/ה מבקש/ת סיור** במיניסייט (`client_showcase_meetings`, ‏`requested`).
2. **גבריאלה מציעה לסוכן/ת** (תוך דקה, בוואטסאפ):

   > תומר, דנה ביקש/ה במיניסייט סיור היום ב-17:00:
   > • הרצל 5, עפולה (בעלים: משה לוי)
   > • הנביאים 3, עפולה (מתווך/ת: רונית כהן)
   >
   > לשלוח לכל הבעלים והמתווכים בקשה לתאם ביקור בסביבות 17:00-18:00? ...
   >
   > [📨 כן, לשלוח לכולם] [לא, אתאם בעצמי]

3. **"כן"** פותח שורה לכל נכס ב-`showing_coord_requests` ושולח מיד. גבריאלה
   עונה מה יצא, למי ולמי לא.
4. **כל נמען/ת מקבל/ת:**

   > שלום משה, כאן תומר יצחק מרימקס עמק. אני מבקש/ת לתאם איתך ביקור בנכס
   > בהרצל 5, עפולה עם לקוחות, היום בסביבות השעה 17:00-18:00.
   > האם זה מתאפשר לך? אשמח לאישור הביקור.
   >
   > [✅ מאשר/ת] [🕒 מבקש/ת לדחות] [לא מתאים, מועד אחר]

5. **הלחיצה** נרשמת (`showing_coord_respond`), גבריאלה מודה לנמען/ת, והסוכן/ת
   מקבל/ת התראה: "✅ משה לוי אישר/ה את הביקור · הרצל 5, עפולה · היום 17:00 ·
   סיור עם דנה".

אותו דבר מה-CRM: בפאנל המיניסייט, מתחת לכל בקשת סיור פתוחה, הכפתור
"📨 תיאום עם הבעלים והמתווכים". אחרי השליחה הבלוק מציג את הסטטוס של כל נמען/ת.

## למי נשלח

| הנכס | הנמען/ת | מאיפה הטלפון |
| --- | --- | --- |
| של הסוכן/ת | הבעלים | `property_owners` |
| של עמית/ה במשרד | העמית/ה | `agency_members.phone` |
| בשת"פ ממשרד אחר | המתווך/ת המקורי/ת | `agency_members.phone` |

נכס של עמית/ה עובר דרך העמית/ה ולא ישר לבעלים: הקשר עם הבעלים שלו/ה.

**מה הנמען/ת אינו/ה רואה:** את שם הלקוח/ה, ואת שאר הנכסים בסיור. מתווך/ת
בשת"פ שמקבל/ת "ביקור עם לקוחות בהרצל 5" לא יודע/ת מה עוד הלקוח/ה רואה היום.

## הכפתורים - ולמה הם נתפסים לפני הכול

| payload | מי לוחץ/ת | איפה נתפס |
| --- | --- | --- |
| `scoord:<y\|n>:<meeting_id>` | הסוכן/ת, על ההצעה | ענף `interactive` של הסוכן/ת ב-`index.ts`, לפני הכותרת |
| `scr:<a\|p\|d>:<token>` | הבעלים / המתווך/ת | `handleMessage`, **לפני זיהוי השולח/ת** - ליד `mtg:` |

השני לפני הזיהוי מאותה סיבה של `mtg:` ([`meeting-client-followup.md`](meeting-client-followup.md)):
בעלים אינו/ה סוכן/ת והיה/הייתה מגיע/ה לבוט הציבורי, ומתווך/ת בשת"פ **הוא/היא**
סוכן/ת - והלחיצה הייתה נכנסת לגבריאלה כאילו נכתבה ביד.

**הסדר של הכפתורים הוא חוזה עם Meta.** בתבנית הכותרות קבועות שם, והקוד שולח
payload לפי האינדקס (`COORD_BUTTONS` ב-`showing-coord.ts`). כותרות: עד 20 תווים
**ו-20 יחידות UTF-16** - "📆 לא מתאים, מועד אחר" הוא 21 יחידות, ולכן הכפתור
השלישי בלי אימוג'י.

## הערוץ

| מצב | מה יוצא |
| --- | --- |
| הנמען/ת כתב/ה למספר ב-23 השעות האחרונות | הודעת כפתורים רגילה |
| אחרת, והסוד `WHATSAPP_SHOWING_COORD_TEMPLATE` מוגדר | התבנית |
| אין אף אחד מהם | `no_channel` - לא נשלח כלום |

רוב הבעלים מעולם לא כתבו למספר של שוק נדל״ן, ולכן **בלי התבנית רוב הבקשות
יהיו `no_channel`**. גם אז אין כשל שקט: הבלוק בפאנל אומר את זה, ולכל נמען/ת
שלא קיבל/ה (אין ערוץ, נכשל, חסם/ה) יש כפתור "💬 לשלוח ממני" - קישור `wa.me`
עם אותו נוסח, מהטלפון של הסוכן/ת.

**ההצעה לסוכן/ת** יוצאת רק בתוך חלון 24 השעות שלו/ה, כמו `property-offers`
(אין תבנית עם כן/לא). הצעה שלא יצאה ממתינה לפעם הבאה שהסוכן/ת כותב/ת לגבריאלה,
כל עוד הבקשה מ-3 הימים האחרונים והסיור עוד לא עבר. ובינתיים - הכפתור ב-CRM.

### התבנית ב-Meta

**WhatsApp Manager → Message Templates → Create**, ‏Language: עברית, ‏Category:
**Utility** (בקשה לתיאום של אירוע מסוים).

```
שלום {{1}},
{{2}}
האם זה מתאפשר לך? אשמח לאישור הביקור.
```

| שדה | ערך |
| --- | --- |
| כפתורים | Quick reply × 3, **בסדר הזה**: `✅ מאשר/ת` · `🕒 מבקש/ת לדחות` · `לא מתאים, מועד אחר` |
| דוגמה ל-`{{1}}` | `משה לוי` |
| דוגמה ל-`{{2}}` | `כאן תומר יצחק מרימקס עמק. אני מבקש/ת לתאם איתך ביקור בנכס בהרצל 5, עפולה עם לקוחות, היום בסביבות השעה 17:00-18:00.` |

`{{2}}` הוא **שורה אחת** (Meta דוחה פרמטר עם ירידת שורה) - `coordLine`.
אחרי האישור: הסוד `WHATSAPP_SHOWING_COORD_TEMPLATE` (ושפה ב-`_LANG`, ברירת
מחדל `he`) ב-Supabase → Edge Functions → Secrets.

## המסד

מיגרציה `20270418090000_showing_coordination.sql`.

| מה | תפקיד |
| --- | --- |
| `showing_coord_requests` | שורה לכל נכס בסיור: יעד, טלפון, `status`, ‏`token` (48 hex), ‏`window_start` |
| `client_showcase_meetings.coord_offer` | ההצעה לסוכן/ת: `sent` / `failed` / `yes` / `no` |
| `agent_showing_coord_start(agent, meeting)` | יוצר את השורות (service_role - הבוט). ‏`showing_coord_request(meeting)` היא העטיפה ל-CRM, עם הזהות מה-JWT |
| `showing_coord_claim` | מסמן `sending` **לפני** השליחה - קריסה אינה שולחת פעמיים |
| `showing_coord_offer_claim` | מסמן `coord_offer = 'sent'` לפני השליחה, מאותה סיבה |
| `showing_coord_respond(token, answer)` | רושם את התשובה ומתריע לסוכן/ת |
| `showing_coord_ready()` | התנאי של ה-cron `showing-coord` (כל דקה) |
| הטריגר `client_showcase_meetings_cancel_coord` | סיור שבוטל או נדחה - מה שעוד ממתין אינו יוצא |

הסטטוסים: `pending` → `sending` → `sent` → `confirmed` / `postpone` / `declined`,
ובדרך: `no_phone`, `no_channel`, `failed`, `opted_out`, `canceled`. לחיצה נוספת
(בפאנל) פותחת מחדש רק את `no_phone`, `no_channel`, `failed` ו-`canceled` - **לא
`opted_out`**: מי שחסם/ה הודעות מהעסק לא מקבל/ת עוד אחת. בקשה שיצאה או נענתה
לא נשלחת פעמיים.

**ההתראה לסוכן/ת היא `agenda_reminder`**, לא סוג חדש: סיור "היום בסביבות 17:00"
ביום שישי לא יכול לחכות לראשון, והסוג הזה עוקף שעות וימים שקטים. היא נושאת
`related_client_id` (פותח את כרטיס הלקוח/ה), ו-`related_agenda_item_id` כשהסיור
כבר אושר ונרשם ביומן.

**הגייט:** `agent_agenda_enabled` (PROFESSIONAL ו-Elite) - ב-`agent_showing_coord_start`
וב-`showing_coord_offer_claim`, ושורה משלו ב-`pricing.html`.

## בדיקה

המיגרציה הורצה פעמיים על Postgres 16 מקומי עם טבלאות מדומות (אידמפוטנטית),
ונבדקו: ההצעה (פעם אחת לסיור, גם כשיש לסוכן/ת כמה שורות שיחה), יצירת הבקשות
לבעלים, למתווך/ת ולנכס בלי טלפון, יצירה חוזרת שאינה כופלת, סוכן/ת אחר/ת
(`not_found`), ה-claim שאינו מחזיר פעמיים, תשובה, תשובה חוזרת (`already`),
שינוי תשובה, טוקן לא קיים, ביטול הסיור שמבטל את הממתינים, ותשובה על בקשה
שבוטלה. וגם `agent_agenda_dispatch` עם ליד קיים וליד שנמחק.

אחרי המיזוג:

```sql
select jobname, schedule from cron.job where jobname = 'showing-coord';
select status, count(*) from showing_coord_requests
 where created_at > now() - interval '7 days' group by 1 order by 2 desc;
```

## מה עוד אפשר

- **הודעת ביטול לנמענים** כשהלקוח/ה מבטל/ת סיור שכבר יצאו עליו בקשות. היום רק
  מה שעוד ממתין נעצר, ומי שכבר אישר/ה ולוחץ/ת שוב מקבל/ת "הביקור בוטל".
- **"מבקש/ת לדחות" עם שעה** - היום זו תשובה בלי שעה, והסוכן/ת חוזר/ת לתאם.
