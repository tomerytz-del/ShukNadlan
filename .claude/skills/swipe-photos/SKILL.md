# תמונות ב-/swipe: טעינה מראש ומדידה

המקור: `assets/swipe.js`, והתיעוד ב-`docs/swipe-mode.md` ("תמונות בלי קפיצה"
ו-"swipe-photos-ahead").

## הכללים

1. **כל טעינה מראש עוברת דרך `warm(u)`** - היא מוותרת על כתובת שכבר התבקשה
   (`WARM`), מבקשת קודם את הטשטוש לקבלת יחס, ואז את הרוחב הנכון (`SRCW`),
   כך שהכרטיס, החימום והקרוסלה פוגעים באותה כתובת במטמון. תמונה שנבקשת ברוחב
   אחר היא הורדה כפולה.
2. **חימום הוא `fetchPriority = 'low'`, והחלפה שמישהו מחכה לה (`swapNow`) היא
   `'high'`.** בלי זה חימום תופס את חיבורי הדפדפן ומעכב תמונה מבוקשת: נמדדו
   חריגים של 2 עד 6 שניות. **הטשטוש של 40px שמקדים את `warm` נשאר בעדיפות
   רגילה, בכוונה:** `go()` מתחיל רק אחריו, ועדיפות נמוכה עליו מעכבת את התמונה
   עצמה בשניות.
3. **חימום חדש בא אחרי שהתמונה העליונה הגיעה** (כמו `warmAhead`, ו-`warmCarousel`
   שנקרא מ-`load` של `swapNow`), ולא מתחרה בה. מאזין שנתלה על הצומת המשותף
   `.sw-cimg` יוצא גם ב-`error`. כשהכתובת זהה לנוכחית אין אירוע `load`, ולכן מתקדמים
   מיד רק אם `img.complete && img.naturalWidth`, ואחרת ממתינים לו.
   **שקופית מיוחדת (`slideKind`) מדלגים עליה ולא עוצרים בה**, והחלון הוא עד שלוש
   שקופיות קדימה (אחרת תמונות רחוקות מורדות לפני הזמן), וכרטיס שנפתח ברילס
   מחמם את `ph[1]` בעדיפות רגילה: זו התמונה האמיתית הראשונה, ו-`firstImg` חימם
   רק את הפוסטר.
4. **כל חימום נוסף עולה בייטים, ו-`lean()` (Save-Data, 2G) משאיר רק את התמונה
   הבאה.** חימום חדש נבדק גם בלי רשת מהירה.
5. **אחורה לא נטען, בכוונה:** תמונה שכבר נראתה כבר במטמון, ובעטיפה מהראשונה
   השקופית האחרונה היא בדרך כלל הצעת ההדמיה (`#viz:invite`) ולא תמונה.
   ‏`slides(p)` מוסיף שקופיות מיוחדות (`#reel`, `#viz:*`), ולכן אינדקס אחרון
   אינו בהכרח כתובת תמונה: `slideKind(u)` לפני כל `warm`.

## מדידה

מכשיר המדידה כאן (`bench_server.py`, `bench.py`) מודד **הקשה עד תמונה גלויה
ומפוענחת** ולא טעינת דף, ולכן אין להחליף אותו ב-`perf-measure/measure.py`.
הוא חולק איתו את אותם מוקשים:

* **אין `context.route`** - יירוט מכבה את מטמון ה-HTTP, ו"חימום" יימדד כאפס.
  במקום זה `window.supabase` מוחלף ב-`add_init_script` (‏getter עם setter ריק,
  כדי שה-CDN לא ידרוס אותו), והתמונות מוגשות משרת מקומי עם
  `Cache-Control: public, max-age=3600` כמו Supabase.
* **שרת התמונות מחקה `render/image/public/...?width=`**, כי `sized()` בונה
  את הכתובת כך.
* **רשת:** 1.6Mb/s ו-RTT 150ms דרך CDP, מעבד פי 4, פלאפון 390×844.
* **`--no-proxy-server`**, כי Chromium בענן עובר דרך הפרוקסי.
* **חמש ריצות לפחות, ושני הכיוונים:** חציון, כמה הקשות איטיות (מעל 150ms)
  **וכמה KB ירדו** - טעינה מראש שמורידה את החציון ומעלה את הבייטים היא עסק,
  לא שיפור נקי.

```sh
S=.claude/skills/swipe-photos
git show origin/main:assets/swipe.js > /tmp/swipe.before.js     # מחוץ לריפו
python $S/bench_server.py 8751 /tmp/swipe.before.js &           # לפני
python $S/bench_server.py 8752 assets/swipe.js &                # אחרי
pip install --quiet playwright
for sc in fwd back next2; do for p in 8751 8752; do
  python $S/bench.py http://127.0.0.1:$p $sc 5 | tail -1; done; done
```

* `fwd` - חמש הקשות קדימה כל 450ms. ‏`next2` - דילוג לכרטיס הבא והקשה על
  תמונותיו. ‏`back` - חזרה אחורה (שני הצדדים במטמון; **שלוש הקשות אחורה
  מגיעות לשקופיות ההדמיה, ו-8000ms שם הוא timeout של המכשיר ולא מדידה**).
