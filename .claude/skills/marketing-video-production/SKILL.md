# הפקת סרטון שיווק

הסרטון הראשון שהופק כך: "מהשיחה לפגישה" (גיוס מתווכים, 10.2026). המקור שלו
ב-`marketing/videos/call-to-meeting/`, וההוראות המלאות ב-`marketing/videos/README.md`.
הספרייה שאליה הסרטון נכנס: `docs/marketing-videos.md`.

## ‏1. Reelkit בסשן ענן - שני דברים, אחרת הכול נכשל

| התסמין | הסיבה | התיקון |
| --- | --- | --- |
| ‏`The Reelkit API returned 403` / ‏`CONNECT tunnel failed, response 403` | ‏`reelkit.cc` אינו ברשימת הדומיינים של הסביבה | המשתמש/ת מוסיף/ה אותו: תפריט הסביבה (אייקון הענן מעל תיבת ההודעה ב-claude.ai/code) ← גלגל השיניים ← Network access: **Custom**, ‏Allowed domains: `reelkit.cc`, **ולסמן** "Also include default list of common package managers" (אחרת npm נחסם). אין לזה קישור ישיר |
| ‏`Cannot reach the Reelkit API` אחרי שהדומיין הותר | ‏`fetch` של Node אינו קורא את `HTTPS_PROXY` | ‏`NODE_USE_ENV_PROXY=1` לפני **כל** פקודת `reelkit` (ו-`NODE_NO_WARNINGS=1` להשתיק אזהרה) |
| ‏`The voice service failed` / ‏`transcription service failed` עם קוד `server_error` | תקלה אצל Reelkit, גם בקול באנגלית | לא לנחש תיקון. לנסות שוב בעוד דקות, ולהציע קול אמיתי (סעיף 4) |

**ההתקנה אוטומטית:** `.claude/hooks/session-start.sh` מתקין בכל סשן ענן את
`reelkit-cli`, את הסקיל שלו (`reelkit install --agent claude`) ואת `librosa`,
וכותב `NODE_USE_ENV_PROXY=1` לסביבה. ידנית: `npm install -g reelkit-cli`
(החבילה `reelkit` ב-npm היא ספרייה אחרת, בלי פקודה).

**ההתחברות לא:** בכל סשן חדש `reelkit whoami`, ואם לא מחובר -
`reelkit auth login --start`, לשלוח את הקישור, ואחרי אישור `--finish`. הטוקן
אינו בריפו ואסור שיהיה.

## ‏2. לפני שמקליטים: תוכנית ואישור

- התסריט, הטקסט שעל המסך ושורה על מה רואים בכל סצנה - **לאישור לפני** הקלטה
  ורינדור. רינדור לוקח כ-10 דקות; תיקון תסריט לוקח דקה.
- **ההוק:** להציע כמה אפשרויות עם המלצה. תוצאה קודם ("שיחה נכנסה? פגישה
  נקבעה!") עבד טוב, ושאלה שהסרטון עונה עליה בסוף.
- **אמת בלבד.** לא מספרים, לא ציטוטים ולא יכולות שהמשתמש/ת לא אמר/ה. אם
  ההבטחה חזקה מהמוצר (למשל "הכול אוטומטי" כשהסוכן/ת עדיין לוחץ/ת "יצירת
  הקישור") - להגיד את זה ולהציע ניסוח מדויק. ‏`docs/` הוא המקור לבדיקה.
- **המסכים מצוירים בקוד ואינם צילומי מסך.** אין ליצור צילום מסך מזויף של
  המערכת בתמונה שנוצרה ב-AI. צילומי מסך אמיתיים עדיפים - לבקש אותם.
- **שיתוף רכיבים:** Reelkit שולח רכיבים חדשים לספרייה שלו אחרי רינדור, אלא
  אם `reelkit init <name> --private` או `REELKIT_NO_SHARE=1`. להגיד למשתמש/ת
  ולכבד את ההחלטה.

## ‏3. עברית על המסך

- גופן עברי אחד (`font("heebo")`), כל מכל `direction: rtl`, שורה לכל אלמנט
  עם `whiteSpace: nowrap` - לא לתת לדפדפן לשבור שורה בעברית.
- **בלי מקף ארוך** בטקסט שעל המסך ובכתוביות (CLAUDE.md).
- ערבוב עברית ואנגלית באותה תווית ("ניסוי A/B · 2 גרסאות") מתהפך. לנסח בלי.
- **תמונת דמות שנוצרה ב-AI** (גבריאלה) - לחתוך החוצה כל טקסט שבתוכה (טאבלט,
  תג שם): הוא ג'יבריש, וזה בולט בטלפון.

## ‏4. קול אמיתי (מומלץ)

קול של מישהו מהמערכת אמין יותר מקול סינתטי, וגם עוקף תקלה בשירות הקול.

1. התסריט שורה-שורה, עם שנייה של שקט בין שורות. מותר לחזור על שורה - לוקחים
   את האחרונה, או את מה שהמשתמש/ת אומר/ת.
2. ‏**לפני ששולחים הקלטה של המשתמש/ת לשרת חיצוני (גם של Reelkit) - לשאול.**
   הדרך שבכלים אינה שולחת: היא מיישרת מול קול סינתטי שמופק **בפרויקט נפרד**
   (‏`reelkit init align --private`), רק לתזמון.
3. ‏`marketing/videos/tools/`: ‏`align_voice.py` (איפה כל שורה, והטייק האחרון
   של שורה שחזרה - ‏`REPEAT_ID`), ‏`align_lines.py` (הצמדה להפסקות ותזמון מילים),
   ‏`build_vo.py` (חיתוך, `atempo`, ו-`assets/voiceovers.json` בפורמט של Reelkit).
   ‏`pip install librosa soundfile`. מודלי זיהוי דיבור לא זמינים בסביבה
   (‏HuggingFace חסום) - זו הסיבה ליישור מול קול סינתטי.
4. **לבדוק את הגבולות באנרגיה, לא רק בתוצאה:** נשימה לפני שורה נראית כמו
   מילה (‏-55dB מול -20dB לדיבור). ‏`reelkit preview` מראה פריים 4 פריימים אחרי
   כל מילה מתוזמנת - לעבור עליהם.
5. **שורות שחזרו בסדר לא צפוי** (כמה ניסיונות לכמה שורות): ‏`match_takes.py` מזהה
   איזה גוש דיבור הוא איזו שורה, ואת הגוש האחרון קובעים ב-`spans.json`.
6. **קצב:** מי שמקליט/ה מהר לא צריך/ה `atempo` - ב"מחפשים דירה" ההקלטה כבר הייתה
   15 שניות, וההאצה השאירה לסצנות פחות משתי שניות. אז `atempo` 1.0 ופער `normal`.
7. "יותר מהר וזורם" = `atempo` 1.1 (בלי שינוי גובה הקול), ופער `tight` בין סצנות.

## ‏5. גרסאות מסך

- ‏Reelkit תומך ב-9:16, ‏16:9 ו-1:1 **בלבד** (לא 4:5).
- ‏9:16 לרילס ולסטורי; 1:1 לפיד באינסטגרם ובפייסבוק.
- **אותו `Video.tsx` לשתיהן:** הקוד מזהה פריים מרובע ומקטין את הבמה של 9:16
  לרצועה שבה התוכן (‏`STAGE`, `WIN_TOP`), והכתוביות, התג והאווטאר יושבים על
  המסגרת המרובעת. מעתיקים את `assets/` ו-`src/` לפרויקט `--aspect 1:1` -
  הקול והתזמון זהים.
- אחרי כל שינוי פריסה - `reelkit preview` ולעבור על **הגרסה המרובעת** בנפרד:
  שם הכתוביות נוטות לכסות את תחתית התוכן.

## ‏6. אחרי הרינדור

1. לבדוק את הקובץ (‏`ffprobe`: יש וידאו ויש שמע), לחלץ כמה פריימים ולהסתכל.
   ‏`reelkit render` מדווח את היחס בין הקול למוזיקה - מתחת לקול ב-10 עד 22dB.
   מוזיקה "שכמעט לא שומעים" = `duckTo` גבוה יותר על `<Music>`.
2. לשלוח את הקובץ (‏`SendUserFile`). לא לומר "שמעתי" - אין האזנה בסביבה.
3. **המקור לריפו, הקבצים לספרייה:** `plan.json` ו-`Video.tsx` ל-
   `marketing/videos/<slug>/`, ושורה ב-`marketing/videos/README.md`. **אין
   mp4, mp3 או תמונות בגיט.** ה-mp4 מועלה בלשונית "סרטונים" (המשתמש/ת -
   לסשן אין גישה לאחסון) עם **רעיון** משותף לכל הגרסאות ו**גרסה** משלו.
4. ניסוי A/B: שינוי **אחד** בין גרסאות, ושתיהן באותו קמפיין עם אותו נוסח
   (‏`docs/marketing-videos.md`, "איך מריצים ניסוי A/B").
